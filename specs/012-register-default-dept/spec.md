# Feature Specification: 小程序注册自动挂载默认组织顶级部门

**Feature Branch**: `012-register-default-dept`
**Created**: 2026-08-08
**Status**: Draft
**Input**: User description: "用户通过微信小程序 注册 将该人员挂载到默认组织的顶级部门"

## Clarifications

### Session 2026-08-08

- Q: 新用户注册时，应该挂载到组织树的哪个节点？ → A: 挂载到默认组织本身（根节点，`parent_id = NULL`）。根组织即是"顶级部门"，不区分为两个独立概念。
- Q: 如何指定哪个组织是"默认组织"？ → A: 系统自动选择 `sort_order` 最小的根节点（`parent_id = NULL`）作为默认组织，无需管理员手动配置。
- Q: 通过微信自动注册的新用户应获得什么权限级别？ → A: 普通成员（member），可访问小程序基础功能（首页、客户管理、个人中心等），无组织管理权限。管理员可后续手动提升。
- Q: 自动挂载完成后，用户是否还需要经过信息完善页面（profile-setup）？ → A: 保留 profile-setup 页面但改为可选的信息完善页（收集姓名、头像等），用户可跳过直接进入首页。
- Q: 自动挂载功能是否仅适用于微信授权登录，还是也包括手机号+密码的自主注册？ → A: 两者都支持：微信授权登录和手机号+密码自主注册均触发自动挂载。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新用户注册自动加入组织 (Priority: P1)

一个新用户首次注册小程序（微信授权登录或手机号+密码注册），系统在完成注册后自动将该用户创建为人员记录，并挂载到默认组织根节点下。用户无需联系管理员手动分配即可直接进入首页开始使用小程序。

**Why this priority**: 这是功能的核心——没有自动挂载，新用户注册后将处于"无组织"状态，无法正常使用小程序功能，当前流程会弹出"请联系管理员创建账号"的阻断提示。

**Independent Test**: 用全新的微信账号授权登录小程序，注册完成后检查该用户在组织人员列表中是否已存在于默认组织的顶级部门下。

**Acceptance Scenarios**:

1. **Given** 系统中已配置默认组织且该组织存在顶级部门，**When** 新用户通过微信授权首次登录小程序并完成注册，**Then** 系统自动为该用户创建人员记录并挂载到默认组织，随后展示可选的信息完善页（用户可跳过直接进入首页）。
2. **Given** 系统中已配置默认组织但该组织暂无任何部门，**When** 新用户通过微信授权首次登录小程序并完成注册，**Then** 系统自动为该用户创建人员记录并关联默认组织，部门字段为空，同时记录一条警告日志供管理员排查。
3. **Given** 系统中未配置默认组织，**When** 新用户通过微信授权首次登录小程序并完成注册，**Then** 系统仍完成用户注册，但人员记录的组织和部门字段均为空，并向用户展示"账号已创建，请联系管理员分配组织部门"的提示。
4. **Given** 系统中已配置默认组织且存在根节点，**When** 新用户通过手机号+密码方式首次注册，**Then** 系统自动创建人员记录并挂载到默认组织，随后展示可选的信息完善页。

---

### User Story 2 - 已有账号绑定微信不重复创建 (Priority: P2)

一个已经在系统中存在的人员记录（由管理员手动创建），通过微信登录绑定已有账号时，系统不应为其重复创建人员记录或修改其已有的组织部门归属。

**Why this priority**: 避免微信绑定流程覆盖管理员已设置的组织架构信息，防止数据错误。

**Independent Test**: 管理员先手动创建一个人员并分配到特定部门，该人员再通过微信授权登录并绑定相同手机号，检查其部门和所属组织是否保持不变。

**Acceptance Scenarios**:

1. **Given** 系统中已存在某个手机号对应的人员记录且已分配部门，**When** 该用户通过微信授权登录并绑定该手机号，**Then** 系统关联微信账号与已有人员记录，不修改其组织和部门归属。
2. **Given** 系统中已存在某人员记录但尚未关联微信，**When** 该用户通过微信授权登录且手机号匹配成功，**Then** 系统仅完成微信绑定，不创建重复人员记录。

---

### User Story 3 - 管理员查看和管理自动挂载的人员 (Priority: P3)

管理员可以在组织人员管理页面查看到通过微信注册自动挂载的新人员，并能手动调整其部门归属（如从顶级部门移动到子部门）。

**Why this priority**: 自动挂载只是初始分配，管理员需要后续能够识别和管理这些自动分配的人员，确保组织架构的准确性。

**Independent Test**: 完成一次新用户微信注册后，管理员登录管理后台，在人员列表中查找该用户，验证其显示的组织和部门信息，并尝试将其移动到另一个部门。

**Acceptance Scenarios**:

1. **Given** 新用户通过微信注册并被自动挂载到默认组织顶级部门，**When** 管理员在人员管理列表中查看，**Then** 该用户出现在列表中，显示所属组织为默认组织、所属部门为顶级部门，来源渠道标记为"微信注册"。
2. **Given** 自动挂载的人员当前在顶级部门下，**When** 管理员将该人员移动到某个子部门，**Then** 人员部门更新成功，该人员在小程序端看到的信息随之更新。

---

### Edge Cases

- **并发注册**: 同一手机号在短时间内发起多次注册请求，系统应确保只创建一条人员记录。
- **默认组织被删除**: 如果管理员删除了当前默认组织（`sort_order` 最小的根节点），系统自动将次小的根节点作为新的默认组织。若组织树中已无任何根节点，回退到"未配置默认组织"场景——用户注册成功但人员记录的组织字段留空，并提示用户联系管理员。
- **微信授权失败**: 用户拒绝微信手机号授权时，注册流程无法完成，不应创建人员记录。
- **已注销用户重新注册**: 之前注销的用户重新通过微信登录时，若原人员记录仅标记为禁用（非物理删除），复用原记录并恢复为启用状态，不修改其组织部门归属；若原记录已物理删除，则按新用户流程创建人员记录并自动挂载。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 自动将组织树中 `sort_order` 最小的根节点（`parent_id = NULL`）作为默认组织，用于新用户注册时的归属分配。若不存在任何根节点，视为"未配置默认组织"。
- **FR-002**: 系统 MUST 在新用户首次注册成功后（无论是微信授权登录还是手机号+密码自主注册），自动创建人员记录并将其关联到默认组织。
- **FR-003**: 系统 MUST 将新注册用户自动挂载到默认组织本身（即组织树的根节点，`parent_id = NULL`）。根组织即为新用户的初始归属节点。
- **FR-004**: 系统 MUST 在自动挂载前检查该手机号是否已存在人员记录，若已存在则仅做微信账号绑定，不重复创建人员记录也不修改已有的组织部门归属。
- **FR-005**: 系统 MUST 在默认组织不存在或未配置时，仍完成用户注册，但人员记录的组织和部门字段留空，并向用户展示"账号已创建，请联系管理员分配组织部门"的友好提示。
- **FR-006**: 系统 MUST 在人员记录上标记来源渠道（如"微信注册"或"管理员创建"），以便管理员区分自动注册人员和手动创建人员。
- **FR-007**: 管理员 MUST 能够在人员管理界面查看和调整自动注册人员的组织部门归属。
- **FR-008**: 系统 MUST 将自动注册的新用户角色设置为普通成员（member），仅可访问基础功能模块，不授予组织管理权限。
- **FR-009**: 系统 MUST 将 profile-setup 页面改为可选的信息完善页（收集姓名、头像等非必填信息），用户可跳过该页面直接进入首页。页面不再弹出"请联系管理员创建账号"的阻断提示。

### Key Entities

- **用户 (User)**: 微信小程序的注册用户，包含微信 OpenID、手机号、注册时间、账号状态等基本信息。
- **人员 (Distributor/Personnel)**: 组织内的人员记录，关联到用户账号，包含所属组织节点、来源渠道（微信注册/管理员创建）等属性。一个用户对应一条人员记录。
- **组织树节点 (Organization Node)**: 系统采用统一组织树模型——组织和部门为同一棵树上的节点，通过 `parent_id` 形成层级。根节点（`parent_id = NULL`）代表一个顶层组织（也是其自身的"顶级部门"），子节点代表该组织下的细分部门。其中一个根节点被标记为默认组织。
- **默认组织 (Default Organization)**: 系统根据规则自动确定的根节点——即组织树中 `sort_order` 最小的根节点（`parent_id = NULL`）。新用户注册时自动归属到此节点。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户从点击微信授权登录到完成注册并进入首页，全流程耗时不超过 30 秒。
- **SC-002**: 新用户注册后自动挂载组织的成功率达到 100%（在默认组织已配置且存在顶级部门的前提下）。
- **SC-003**: 同一手机号无论注册多少次，系统中仅存在一条人员记录（不产生重复人员记录）。
- **SC-004**: 已有人员记录的账号绑定微信后，其组织部门归属保持不变的准确率达到 100%。
- **SC-005**: 新用户注册后可直接进入首页并使用基础功能，不再出现"请联系管理员创建账号"的阻断提示，管理员人工介入需求降为零（针对注册挂载场景）。

## Assumptions

- 系统采用统一组织树模型（组织和部门为同一棵树中的节点），参考 specs/004-org-personnel-management。
- 默认组织由系统自动选定（`sort_order` 最小的根节点，即 `parent_id = NULL`），无需管理员手动配置。
- 新用户挂载目标为默认组织根节点本身（根组织 = 顶级部门），不区分独立的概念。
- 新注册用户的默认角色为普通成员（member），仅可访问基础功能，无组织管理权限。管理员可后续手动提升为管理员。
- 微信登录流程（`wx.login` + 手机号授权）及手机号+密码登录流程均已存在，本功能在现有登录流程基础上增加注册后的组织挂载步骤。
- 用户注册时必须有手机号（通过微信手机号授权或手机号+密码登录方式），手机号作为匹配已有人员记录的唯一键。
