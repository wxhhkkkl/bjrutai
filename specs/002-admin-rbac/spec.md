# Feature Specification: 后台管理 RBAC 权限管理

**Feature Branch**: `002-admin-rbac`  
**Created**: 2026-07-31  
**Status**: Draft  
**Input**: User description: "后台管理平台，账户管理页面，要有RBAC相关的子菜单，可以用于管理管理员用户、角色、权限，默认有一个系统管理员角色，可以管理所有的权限，不能被删除。默认admin关联到这个系统管理员角色上。"

## Clarifications

### Session 2026-07-31

- Q: 权限管理是独立子页面还是嵌入角色编辑？ → A: 两个子菜单（管理员列表 + 角色管理），权限在角色编辑弹窗中通过勾选树配置

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员账户管理 (Priority: P1)

管理员登录后台后，在"账户管理"菜单下可以查看、创建、编辑、启用/禁用其他管理员账户，并为其分配角色。

**Why this priority**: 多管理员协作的基础——必须先能管理账户才能谈权限分配。

**Independent Test**: 登录后进入账户管理页面，创建新管理员、分配角色、禁用账户、重新启用，整个流程独立可测。

**Acceptance Scenarios**:

1. **Given** 已登录为管理员，**When** 进入账户管理→管理员列表，**Then** 看到所有管理员账户列表（用户名、状态、所属角色、创建时间）
2. **Given** 在管理员列表页，**When** 点击"新建管理员"，填写用户名、密码、选择角色并提交，**Then** 新管理员创建成功且可用所选角色登录
3. **Given** 存在一个活跃的管理员，**When** 点击"禁用"，**Then** 该管理员无法登录，列表中状态变为"已禁用"
4. **Given** 存在一个被禁用的管理员，**When** 点击"启用"，**Then** 该管理员恢复登录能力

---

### User Story 2 - 角色管理与权限配置 (Priority: P2)

管理员可以在角色管理页面创建、编辑、删除自定义角色，每个角色通过权限勾选树关联一组权限。系统预定义一组权限（按功能模块分组的操作权限），在角色编辑弹窗中通过勾选完成配置。

**Why this priority**: 角色是权限的载体，定义好角色才能实现精细化权限控制。权限配置是角色管理的子功能，不独立成页。

**Independent Test**: 创建新角色，在编辑弹窗中通过权限树配置权限并保存；编辑已有角色的权限；删除未被使用的角色；查看系统管理员角色的权限树全选状态。

**Acceptance Scenarios**:

1. **Given** 在角色列表页，**When** 点击"新建角色"，输入角色名称、勾选权限树中的权限并保存，**Then** 新角色出现在列表中
2. **Given** 进入角色编辑页面，**When** 查看权限树，**Then** 看到按功能模块分组的权限列表（如：账户管理、客户管理、业绩贡献、数据报表等），每个模块下有对应的操作权限
3. **Given** 在权限配置中，**When** 勾选/取消勾选某个权限并保存，**Then** 该角色的权限立即更新，关联管理员下次登录时获得更新后的权限
4. **Given** 存在一个未被任何管理员使用的角色，**When** 点击"删除"，**Then** 角色被移除
5. **Given** 存在"系统管理员"角色，**When** 查看该角色，**Then** 不显示删除按钮，且角色名称不可修改

---

### User Story 3 - 系统管理员默认角色（不可删除）(Priority: P1)

系统首次启动时自动创建"系统管理员"角色（拥有全部权限），且该角色不可删除。默认 admin 账户自动关联到此角色。

**Why this priority**: 没有超级管理员角色系统无法管理，且这是用户明确要求的核心约束。

**Independent Test**: 系统启动后检查角色列表，确认存在"系统管理员"角色且无删除按钮；检查 admin 账户的角色分配。

**Acceptance Scenarios**:

1. **Given** 系统首次启动，**When** 查看角色列表，**Then** 存在"系统管理员"角色，拥有全部权限
2. **Given** "系统管理员"角色存在，**When** 查看角色操作选项，**Then** 不显示删除按钮
3. **Given** 系统首次启动，**When** 查看 admin 账户详情，**Then** 其已关联到"系统管理员"角色
4. **Given** "系统管理员"角色存在，**When** 通过 API 尝试删除此角色，**Then** 返回错误提示"系统管理员角色不可删除"

---

### Edge Cases

- 删除角色时如果角色已被分配给管理员，应拒绝删除并提示"该角色已被 N 个管理员使用，请先取消分配"
- 禁用正在登录的管理员账户后，其已有会话应在 token 过期后自然失效（当前不强制踢出）
- 新建管理员时用户名为空或已存在，应给出明确的校验提示
- 角色名重复时拒绝创建
- admin 账户本身不可被禁用或删除

## Requirements *(mandatory)*

### Functional Requirements

**前端 - 菜单结构**:
- **FR-001**: "账户管理"菜单项下须包含两个子菜单：管理员列表、角色管理。权限的配置在角色创建/编辑弹窗中通过权限勾选树完成，不作为独立子页面。
- **FR-002**: 菜单须支持折叠/展开子菜单，当前活跃子菜单高亮

**前端 - 管理员列表页**:
- **FR-003**: 列表展示所有管理员账户（用户名、状态、角色、创建时间），支持分页
- **FR-004**: 支持新建管理员（用户名、密码、角色分配）
- **FR-005**: 支持编辑管理员（修改密码、重新分配角色）
- **FR-006**: 支持启用/禁用管理员账户
- **FR-007**: admin 账户行不显示禁用和删除操作

**前端 - 角色管理页**:
- **FR-008**: 列表展示所有角色（名称、权限数量、创建时间）
- **FR-009**: 支持新建角色（名称 + 权限勾选）
- **FR-010**: 支持编辑角色（修改名称、修改权限配置）
- **FR-011**: 支持删除角色（仅未被分配且非系统管理员角色）
- **FR-012**: "系统管理员"角色行不显示删除按钮且名称不可编辑

**前端 - 权限配置**:
- **FR-013**: 权限按功能模块分组展示（如：账户管理、客户管理、业绩贡献、资质审核、报表、文章、推广码等）
- **FR-014**: 权限以勾选框（checkbox）形式呈现，每个模块支持全选/取消全选
- **FR-015**: 权限配置结果以 `{ "permissions": ["scope.action", ...] }` 格式保存至后端

**后端 - 默认数据播种**:
- **FR-016**: 系统首次启动时自动创建"系统管理员"角色，包含所有预定义权限
- **FR-017**: "系统管理员"角色标记为不可删除（is_system 字段或名称硬保护）
- **FR-018**: 默认 admin 账户自动关联到"系统管理员"角色
- **FR-019**: 删除角色的 API 须检查是否为系统保留角色，若是则拒绝
- **FR-020**: 删除角色的 API 须检查是否有关联的管理员，若有则拒绝

### Key Entities

- **管理员账户 (AdminAccount)**: 用户名、密码哈希、状态（活跃/禁用/锁定）、关联角色列表
- **角色 (Role)**: 角色名称、权限配置（JSON）、`is_system` 布尔标记（系统保留角色不可删除，名称不可修改）
- **权限 (Permission)**: 由前端定义的权限标识符，格式为 `{模块}.{操作}`，如 `accounts.read`、`accounts.write`、`customers.read`

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可在 2 分钟内完成一个新管理员账户的创建和角色分配
- **SC-002**: 角色权限变更后，关联管理员重新登录即可获得新权限（无须其他操作）
- **SC-003**: "系统管理员"角色在任何情况下无法被删除（UI 和 API 均阻止）
- **SC-004**: 所有 RBAC 管理操作（CRUD 管理员、CRUD 角色）均有明确的成功/失败反馈

## Assumptions

- 后端角色和账户 CRUD API 已基本就绪（`/api/v1/admin/accounts`、`/api/v1/admin/roles`），前端聚焦于页面实现和交互
- 权限的"强制执行"暂不在本次范围——当前阶段权限列表返回给前端用于 UI 控制，服务端基于 `user_type` 做粗粒度鉴权
- 管理后台使用 Element Plus 组件库，遵循已有的页面和组件模式
- 系统管理员角色通过 `is_system` 布尔字段（需在 Role 模型新增）来标识，默认为 `False`
- 权限列表由前端常量文件定义，作为角色编辑时的选项来源
