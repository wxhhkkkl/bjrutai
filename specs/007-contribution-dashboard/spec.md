# Feature Specification: 业绩贡献页面增强（趋势/排名/统计/最新明细）

**Feature Branch**: `007-contribution-dashboard`
**Created**: 2026-08-04
**Status**: Draft
**Input**: User description: "业绩贡献页面 需要可以按时间查询所有人的业绩；一进入可以看总体业绩的按月趋势；可以按组织结构查看各组织当月的业绩排名；可以查看个人当月业绩的排名；需要有一些简单的统计数据展示；可以直接看到最新的业绩贡献明细30条；可以查看绑定用户数量的排名；"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 业绩总览：时间查询 + 月度趋势 + 统计 (Priority: P1)

管理员进入"业绩贡献"页面，默认即可看到**总体业绩的按月趋势**与一组**简单统计数据**（如当月总业绩、累计业绩、组织数、人员数、绑定用户数等）。页面支持**按月查询**所有人的业绩贡献（默认当前月份，可切换任意单月），查询结果与明细一致。

**Why this priority**: 这是业绩贡献页的总览能力，为管理员提供全局视图与趋势判断，是排名与明细的数据前提，属 P1。

**Independent Test**: 进入页面默认看到月度趋势与统计；切换时间范围后趋势/统计/明细随之更新并与数据一致。

**Acceptance Scenarios**:

1. **Given** 管理员进入业绩贡献页, **When** 页面加载, **Then** 默认展示总体业绩按月趋势（近若干个月）与统计数据
2. **Given** 管理员选择月份, **When** 查询, **Then** 展示该月所有人的业绩贡献明细与汇总，结果与明细数据一致
3. **Given** 管理员查看统计数据, **When** 核对, **Then** 统计值与现有业绩/贡献体系数据一致（如当月总业绩=当月各明细之和）

---

### User Story 2 - 组织当月业绩排名 (Priority: P1)

管理员可以**按组织结构查看各组织当月的业绩排名**——了解各组织当月业绩贡献的高低顺序。

**Why this priority**: 组织维度排名是业绩分析的核心视角，帮助定位高/低业绩组织，属 P1。

**Independent Test**: 查看组织当月业绩排名 → 核对排名顺序与各组织贡献值汇总一致。

**Acceptance Scenarios**:

1. **Given** 管理员进入组织业绩排名, **When** 选择当月, **Then** 展示各组织当月业绩贡献排名（按贡献值从高到低）
2. **Given** 排名展示, **When** 核对, **Then** 每个组织的业绩值与组织内人员贡献值汇总一致
3. **Given** 组织树调整（下级组织迁移）, **When** 重新查看排名, **Then** 组织归属与业绩随之正确归属
4. **Given** 管理员需要查看特定组织范围, **When** 在组织结构树中选择某组织, **Then** 排名列表筛选中该组织及其全部下级组织的业绩排名（全局列表 + 树筛选，已确认）

---

### User Story 3 - 个人当月业绩排名 (Priority: P1)

管理员可以查看**个人当月业绩排名**——各人员（分销员）当月业绩贡献的高低顺序。

**Why this priority**: 个人排名定位业绩优异的个人，辅助激励与运营，属 P1。

**Independent Test**: 查看个人当月业绩排名 → 核对排名与个人贡献值一致。

**Acceptance Scenarios**:

1. **Given** 管理员查看个人业绩排名, **When** 选择当月, **Then** 展示各人员当月业绩贡献排名（按贡献值从高到低）
2. **Given** 排名展示, **When** 核对, **Then** 每个人员的业绩值与其当月贡献记录汇总一致
3. **Given** 人员停用或调整组织, **When** 查看排名, **Then** 人员按当前归属展示

---

### User Story 4 - 绑定用户数量排名 (Priority: P1)

管理员可以查看**绑定用户数量的排名**——提供**个人维度**（各分销员当前累计已绑定客户数）与**组织维度**（组织及全部下级人员的绑定客户总数）两种排名（已确认）。

**Why this priority**: 绑定客户数是业务规模的直接体现，与业绩并列的运营指标，属 P1。

**Independent Test**: 查看个人/组织绑定数量排名 → 核对排序与实际绑定客户数一致。

**Acceptance Scenarios**:

1. **Given** 管理员查看个人绑定数量排名, **When** 查看, **Then** 各分销员按当前累计已绑定客户数从高到低展示
2. **Given** 管理员查看组织绑定数量排名, **When** 查看, **Then** 各组织按组织及全部下级人员绑定客户总数从高到低展示
3. **Given** 排名展示, **When** 核对, **Then** 每个主体的绑定数量与实际已绑定客户数一致

---

### User Story 5 - 最新业绩贡献明细 (Priority: P2)

业绩贡献页默认直接展示**最新的业绩贡献明细 30 条**（最近发生的贡献记录），无需额外操作即可看到最新动态。

**Why this priority**: 最新明细让管理员快速了解最新业绩动态，是"进入可见"的补充信息，故为 P2。

**Independent Test**: 进入页面默认看到最新 30 条业绩贡献明细，且确为最近发生的记录。

**Acceptance Scenarios**:

1. **Given** 管理员进入业绩贡献页, **When** 查看明细区, **Then** 默认展示最新 30 条业绩贡献明细
2. **Given** 明细展示, **When** 核对, **Then** 明细按发生时间倒序，条数为最近 30 条
3. **Given** 有新的业绩贡献产生, **When** 刷新, **Then** 最新明细随之更新

---

### Edge Cases

- 时间范围内无业绩数据：趋势/统计/排名显示空态或 0，明细为空
- 组织下无人员或无业绩：组织排名中该组织业绩为 0 或排在末尾
- 无绑定客户的人员/组织：绑定数量排名中为 0
- 当月无数据但历史有：趋势图仍展示历史月份
- 人员同业绩值并列：排名并列处理（同一名次）
- 组织树为多根森林：各根组织独立参与排名
- 排名数据量大：排名列表需支持分页或 Top-N 展示
- 数据一致性：排名/统计与明细、与既有业绩贡献体系数值一致（核对偏差 0）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 业绩贡献页必须支持按月查询所有人的业绩贡献，默认展示当前月份（单月口径，可切换任意单月，不支持任意日期区间，已确认）
- **FR-002**: 页面进入时默认展示总体业绩按月趋势（近 N 个月）
- **FR-003**: 页面必须展示简单统计数据（如当月总业绩、累计业绩、组织数、人员数、绑定用户数等）
- **FR-004**: 系统必须支持按组织结构查看各组织当月的业绩排名：默认展示全局组织业绩排名列表（按贡献值从高到低），并支持通过组织结构树筛选某组织及其全部下级组织的排名（已确认）
- **FR-005**: 系统必须支持查看个人当月业绩排名（按贡献值从高到低）
- **FR-006**: 系统必须支持绑定用户数量排名：提供个人维度（分销员当前累计已绑定客户数）与组织维度（组织及全部下级人员绑定客户总数）两种排名（已确认）
- **FR-007**: 页面默认直接展示最新 30 条业绩贡献明细（按发生时间倒序）
- **FR-008**: 排名、统计、趋势数据必须与既有业绩/贡献体系数据一致（同源、偏差为 0）

### Key Entities *(include if feature involves data)*

- **业绩贡献 (ContributionRecord)**: 个人业绩贡献记录。含归属分销员、客户、贡献值、类别、状态、发生/结算时间。排名的数据基础。
- **组织 (Organization)**: 组织结构树节点。组织业绩排名按组织聚合贡献值。
- **分销员 (Distributor)**: 个人业绩与绑定客户数的归属主体；组织业绩由组织下人员聚合。
- **客户 (Customer)**: 绑定客户数排名的统计对象（已绑定客户数）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 进入业绩贡献页 2 秒内展示月度趋势与统计数据
- **SC-002**: 时间范围查询结果与明细数据一致（汇总=明细之和，偏差为 0）
- **SC-003**: 组织业绩排名与各组织贡献值汇总一致（核对偏差为 0）
- **SC-004**: 个人业绩排名与个人当月贡献记录汇总一致（核对偏差为 0）
- **SC-005**: 绑定用户数量排名与实际绑定客户数一致（核对偏差为 0）
- **SC-006**: 页面默认展示的最新明细确为最近 30 条（按发生时间倒序）

## Assumptions

- 业绩/贡献值沿用现有体系（`ContributionRecord.points`）；排名与统计均基于贡献值，只显示数值不显示金额
- 时间查询为**单月口径**：默认当前月份，可切换任意单月，不支持任意日期区间（已确认）
- 月度趋势展示近 12 个月（默认），可调整
- 绑定用户数量默认指"当前已绑定（BOUND）客户数"
- 组织业绩排名默认全局列表 + 组织结构树筛选（某组织及其子树）（已确认）
- 绑定用户数量排名提供个人与组织两种维度（已确认）
- 排名列表支持 Top-N 或分页，避免一次性加载全部数据
- 本迭代为管理后台侧（业绩贡献页），小程序端个人/组织业绩视图不在本迭代范围
- 排名与统计按"当月"口径（用户描述），时间范围查询针对明细/总览
