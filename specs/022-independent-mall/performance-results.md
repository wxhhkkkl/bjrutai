# MySQL并发与性能实测

更新：2026-11-08；任务：T129；数据来源：本机一次隔离测试运行。

## 环境与命令

- 后端实际连接本机 Docker runner 新建的 loopback-only、TLS MySQL 测试实例；服务端版本：**MySQL 8.0.46**，镜像配置为`mysql:8.0`。runner 使用独立随机库名前缀、端口和凭据，不读取应用`.env`或渠道/COS凭据，并在退出时清理本轮测试资源。
- 命令：`bash scripts/test-mall.sh --backend-mysql`。MySQL 子套件 **44 passed**，pytest报告总时长 **15.73 秒**；runner 的目标 runner 单元测试另有 **12 passed**。
- 并发窗口使用`time.perf_counter()`测量；订单/地址/报价测试数据准备不计入窗口。测试本身另外校验库存流水、命令唯一性及最终状态，指标代表本机这一次合成工作负载。

## 测量结果

| 场景 | 并发负载与判定 | 实测时间 |
|---|---|---:|
| 末件争抢 | 100个独立买家同时提交，恰有1个订单创建；库存归零、reserved为1，只有1条明细与1条占用流水 | **0.406秒**（约246.5次提交尝试/秒） |
| 幂等重放 | 同一买家对同一报价同时发起20次同键订单创建；全部返回同一订单，仅1条命令、库存仅占用一次 | **0.151秒** |
| 逆序多SKU | 2个买家以反向SKU顺序同时下单；一个成功、一个过期报价失败，无部分订单/库存占用 | **0.036秒** |
| 欠款应用与积分核销 | 两个独立InnoDB会话竞争，保留历史并保证调整应用/积分核销只发生一个合法结果 | **0.025秒** |
| 双worker租约 | 两worker并发领取不同任务；租约过期后新worker可重领，旧worker无法完成任务 | MySQL用例 **0.05秒** |
| 支付worker租约恢复 | 过期租约后先查原支付身份；提交后崩溃/事实落库失败会重查并只生成一次消费来源 | 用例分别 **0.14秒**、**0.19秒** |

## 解释边界

这是单机、本机 Docker、单次合成测量，不是生产吞吐容量、稳定性承诺或SLA；没有测P50/P95/P99、长时间饱和、真实网络/云数据库、多地域延迟或实际支付服务。100次/秒指标是并发的订单创建尝试数除以窗口时间，不代表100笔成功交易。测试使用fake支付渠道，不发起真实资金请求。既有SQLAlchemy/Pydantic/JWT/pytest-asyncio弃用告警不影响44项通过结果。
