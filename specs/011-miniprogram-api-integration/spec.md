# Feature Specification: 小程序前后端 API 集成与 Mock 替换

**Feature Branch**: `api-link`
**Feature Directory**: `011-miniprogram-api-integration`
**Created**: 2026-08-07
**Status**: Draft
**Input**: User description: "现有小程序页面已开发完成，后端接口已对齐，在独立分支进行前后端联调，并将页面模拟数据替换为真实后端数据。"

## Clarifications

### Session 2026-08-07

- Q: 本次联调是否重新设计页面？→ A: 不重新设计；保留现有已确认 UI、页面路由和主要交互，只替换数据来源并补齐真实边界状态。
- Q: 旧规格与新规格字段冲突时以什么为准？→ A: 登录与组织身份以 004 为准，绩效以 008 为准，消费金额口径以 009 为准；001 仅作为未被后续规格覆盖部分的基础契约。实施前必须形成无冲突的页面—接口—字段矩阵。
- Q: Mock 是否全部删除？→ A: 不删除开发演示能力，但必须显式启用；生产及体验环境默认且强制使用真实接口，不得回退到 Mock。
- Q: 是否允许小程序直连数据库或哈尔滨儒泰接口？→ A: 不允许；小程序只访问北京后端 `/api/v1`，外部系统调用、签名、重试和幂等均由后端负责。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 真实登录与可靠会话 (Priority: P1)

分销员可以使用手机号和密码登录；首次登录需要完成微信绑定，之后可以通过微信快捷登录。登录成功后，系统根据真实账户、组织角色和权限进入正确页面，并能在访问令牌过期后恢复会话。退出登录后，旧会话立即失效。

**Why this priority**: 所有业务页面都依赖真实身份和授权范围；会话不可靠时，后续任何联调数据都不可信。

**Independent Test**: 使用一个已激活账户完成手机号登录、首次微信绑定、重新打开小程序、令牌过期刷新、微信快捷登录和退出登录，整个流程不读取模拟会话。

**Acceptance Scenarios**:

1. **Given** 有效分销员账户尚未绑定微信, **When** 使用手机号和密码登录, **Then** 返回真实会话并引导完成微信绑定，绑定成功后进入工作台
2. **Given** 账户已经绑定微信, **When** 用户完成微信快捷登录, **Then** 系统识别同一账户并进入与角色和权限匹配的工作台
3. **Given** 访问令牌已过期且刷新令牌有效, **When** 用户访问受保护业务数据, **Then** 系统恢复会话并完成原请求，用户不需要重新登录
4. **Given** 刷新令牌无效或已撤销, **When** 用户访问受保护页面, **Then** 清除本地会话并返回登录页，不出现循环刷新
5. **Given** 用户确认退出登录, **When** 退出完成, **Then** 服务端会话和本地凭证均失效，返回登录页且不能通过返回操作重新进入业务页
6. **Given** 账户未激活、被禁用或无页面权限, **When** 登录或访问页面, **Then** 展示明确且不泄露敏感信息的状态，不使用模拟身份绕过限制

---

### User Story 2 - 工作台与个人中心展示真实账户数据 (Priority: P1)

登录用户在首页、我的页面、账号信息和通知入口看到与当前真实账户一致的姓名、组织、角色、业务摘要和消息状态；组织管理员只看到其授权组织范围内的入口与数据。

**Why this priority**: 工作台是登录后的首屏，也是验证身份、权限、组织范围和核心摘要是否正确的最短联调闭环。

**Independent Test**: 分别使用普通分销员和组织管理员登录，核对首页、个人中心、账号信息及组织入口与后端账户、权限和组织数据一致。

**Acceptance Scenarios**:

1. **Given** 普通分销员已登录, **When** 打开首页和我的页面, **Then** 展示本人真实账户、客户和消费摘要，不展示组织管理员专属入口
2. **Given** 组织管理员已登录, **When** 打开首页和我的页面, **Then** 展示本人信息及被授权的组织入口，数据范围不超出授权组织子树
3. **Given** 用户更新允许编辑的账号资料, **When** 保存成功并重新进入页面, **Then** 页面展示后端保存后的最新数据
4. **Given** 摘要或通知列表为空, **When** 页面加载完成, **Then** 展示已定义的空状态，不回填模拟记录
5. **Given** 接口失败或用户无权限, **When** 页面加载, **Then** 分别展示可重试错误状态或无权限状态，不保留上一账户的旧数据

---

### User Story 3 - 客户、绑定与跟进形成真实业务闭环 (Priority: P1)

有权限的用户可以查看授权范围内的客户列表和详情，执行搜索、筛选、分页、资料编辑、跟进记录和客户绑定，并能查询真实处理结果。所有提交动作可防止重复写入，敏感信息始终按照最新规则脱敏。

**Why this priority**: 客户及绑定是小程序的核心业务链路，也是页面 Mock 替换中数据结构和状态最多的部分。

**Independent Test**: 从客户列表进入详情，编辑允许修改的字段，新增跟进，提交一次客户绑定并查看处理结果；随后核对后端数据、审计记录和页面展示一致。

**Acceptance Scenarios**:

1. **Given** 用户拥有客户读取权限, **When** 搜索、筛选或滚动加载客户, **Then** 返回授权范围内的真实数据且分页无重复、无遗漏
2. **Given** 用户打开客户详情, **When** 切换基本信息、服务记录和消费记录, **Then** 各页签展示同一客户的后端数据，金额和状态采用最新口径
3. **Given** 用户修改客户资料或保存跟进记录, **When** 后端确认成功, **Then** 页面展示最新记录；失败时保留用户输入并允许安全重试
4. **Given** 用户快速重复点击提交绑定, **When** 网络请求尚未完成, **Then** 只产生一次有效业务提交
5. **Given** 绑定结果为成功、待匹配、失败或处理中, **When** 用户查看记录和结果页, **Then** 页面准确映射后端状态并提供相应后续动作
6. **Given** 用户没有目标客户权限, **When** 通过历史链接或手工参数访问, **Then** 后端拒绝且小程序显示无权限状态，不展示客户数据
7. **Given** 任一客户数据包含手机号、身份证号或医保账户, **When** 后端响应并在页面展示, **Then** 所有敏感字段保持脱敏且不会写入日志或错误提示

---

### User Story 4 - 消费业绩与绩效使用统一真实口径 (Priority: P1)

分销员可以查看本人消费金额概览、趋势、账单明细和绩效预估/已确认结果；组织管理员可以查看授权组织的消费和绩效数据。所有金额以后端整数分为来源，前端统一转换为元展示。

**Why this priority**: 009 已将“贡献值”调整为“消费金额”，联调必须消除旧 Mock 与旧字段，否则不同页面会出现口径不一致。

**Independent Test**: 选择同一分销员和月份，对照后端账单、首页摘要、消费页、客户详情、个人绩效和组织绩效，所有可比金额与状态一致。

**Acceptance Scenarios**:

1. **Given** 用户存在已支付账单, **When** 查看消费概览、趋势和明细, **Then** 金额、月份、状态和客户信息与后端账单一致
2. **Given** 用户切换月份或加载更多明细, **When** 请求完成, **Then** 查询条件、分页游标和页面内容保持一致，不混入上一条件的数据
3. **Given** 当前月尚未审核确认, **When** 用户查看绩效, **Then** 展示当前月预估，不把未确认月份标记为已确认
4. **Given** 历史月份已经审核确认, **When** 用户查看绩效, **Then** 展示冻结结果，且与管理端同一核算结果一致
5. **Given** 组织管理员访问组织业绩, **When** 查看汇总、成员和下级组织, **Then** 仅展示授权组织子树，金额统一按分转元
6. **Given** 旧契约字段与 009 字段同时存在或缺失, **When** 联调校验响应, **Then** 按最新契约处理并明确报错，不静默使用旧 Mock 补齐

---

### User Story 5 - 资料、资质、推广码、反馈与通知接入真实服务 (Priority: P2)

用户可以维护个人资料、上传头像或资质文件、查看资质状态、获取推广码、提交反馈和查看通知；提交结果能够在重新进入页面后从后端恢复。

**Why this priority**: 这些功能不是首个数据闭环的阻塞项，但决定小程序能否脱离演示状态完整使用。

**Independent Test**: 更新账号资料，上传一份合规文件并提交资质，获取推广码，提交反馈并查看通知；重新启动小程序后核对状态仍由后端恢复。

**Acceptance Scenarios**:

1. **Given** 用户选择符合要求的头像或资质文件, **When** 上传和提交成功, **Then** 后端保存文件引用，页面显示最新资料或审核状态
2. **Given** 文件类型、大小或内容不符合要求, **When** 用户尝试提交, **Then** 页面显示明确校验结果且不产生无效业务记录
3. **Given** 用户资质状态发生变化, **When** 重新进入状态页或首页, **Then** 展示后端最新状态及对应操作入口
4. **Given** 已通过资质的用户请求推广码, **When** 页面加载或刷新, **Then** 展示后端生成的有效推广码和统计数据
5. **Given** 用户提交反馈, **When** 提交成功, **Then** 生成真实反馈记录；网络失败时保留文字和待上传附件
6. **Given** 用户查看或标记通知已读, **When** 操作完成, **Then** 列表和未读状态与后端一致

---

### User Story 6 - 在真实网络边界下稳定运行 (Priority: P2)

用户在弱网、超时、服务异常、登录过期和重复操作时得到一致反馈，可以在安全条件下重试，且不会看到其他账号的缓存数据或被静默切换到 Mock。

**Why this priority**: 联调不仅要验证成功响应，还必须验证真实环境中最常见的失败边界和数据安全。

**Independent Test**: 对核心用户旅程分别模拟超时、断网、401、403、500、格式错误和快速重复点击，核对页面状态、重试行为、会话清理和服务端写入次数。

**Acceptance Scenarios**:

1. **Given** 请求超时或网络断开, **When** 用户执行读操作, **Then** 页面停止加载并展示可重试状态，不无限等待
2. **Given** 写操作结果未知, **When** 用户重试, **Then** 系统通过同一业务幂等标识避免重复写入
3. **Given** 后端响应结构不符合统一契约, **When** 小程序解析响应, **Then** 显示受控错误并记录不含敏感数据的诊断信息
4. **Given** 用户从账户 A 退出后登录账户 B, **When** 打开任一业务页, **Then** 不展示账户 A 的内存或本地缓存数据
5. **Given** 体验版或生产版构建, **When** 后端不可用, **Then** 页面展示真实错误，不自动使用 Mock 数据伪装成功

### Edge Cases

- 多个受保护请求同时收到 401 时，只允许一次有效刷新过程；其余请求等待同一结果，刷新失败则统一退出登录
- 微信登录 code 已过期或被使用时，必须重新获取 code，不重复发送失效 code
- 手机号密码登录成功但微信绑定中断时，应保留受限登录态并可继续绑定，不提前开放完整业务权限
- 用户账号在会话期间被禁用、调岗或取消组织管理员身份时，下次鉴权后必须立即收敛权限和数据范围
- 分页请求返回空页、重复游标或数据在翻页期间变化时，不得出现无限加载或重复展示
- 用户在切换月份、筛选条件或页面后收到旧请求响应时，旧响应不得覆盖当前页面条件的数据
- 写请求超时但后端实际成功时，重试不得生成重复客户、绑定、跟进、反馈或资质记录
- 金额为 0、负数退款、部分退款或超大金额时，显示与后端账单状态和整数分口径一致
- 文件上传成功但业务提交失败时，应允许复用已上传文件或明确清理策略，不反复上传
- 后端返回未知枚举、缺少必填字段或非统一响应包时，页面进入受控错误状态，不使用假数据补齐
- 空列表、无权限、资源不存在、业务冲突和系统异常必须使用不同状态表达
- 调试工具缓存过期 Token、旧 Demo Session 或旧账户数据时，真实会话初始化不得受其影响

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 小程序必须只通过北京后端版本化 API 获取和修改业务数据，不得直连数据库或哈尔滨儒泰接口
- **FR-002**: 实施前必须建立覆盖所有接入页面的“页面—用户动作—接口—请求字段—响应字段—状态映射—契约来源”矩阵，并解决全部已知契约冲突
- **FR-003**: 契约优先级必须为：004 的登录与组织身份、008 的绩效、009 的消费金额；001 仅用于未被后续规格覆盖的接口
- **FR-004**: 所有 API 响应必须按照统一包 `{code, message, data, requestId, serverTime}` 校验；HTTP 失败和业务失败必须分别识别
- **FR-005**: 所有受保护请求必须携带当前有效访问令牌，且不得把令牌写入日志、页面数据、错误提示或分享参数
- **FR-006**: 系统必须支持手机号密码登录、首次微信绑定、微信快捷登录、当前会话查询、令牌刷新和退出登录完整生命周期
- **FR-007**: 访问令牌失效时系统必须安全恢复原请求；刷新失败时必须清除全部账户缓存并返回登录页，禁止无限刷新
- **FR-008**: 账户身份、组织角色、权限和业务入口必须来自真实会话，不得通过 Demo Session 推断或覆盖
- **FR-009**: 环境配置必须明确区分本地开发、体验和生产；体验与生产必须使用 HTTPS 合法域名且不得包含密钥或生产凭证
- **FR-010**: Mock 只能通过明确的开发开关启用；体验和生产构建必须强制关闭 Mock，并在真实接口失败时展示错误
- **FR-011**: 首页、客户、消费、个人中心及其二级页面必须移除生产路径对 `mock/` 和固定业务记录的依赖
- **FR-012**: 每个联网页面必须支持适用的加载、成功、空数据、错误和无权限状态，重试不得重复绑定事件或业务提交
- **FR-013**: 列表接口必须按其契约支持分页、加载更多、筛选和搜索，并避免旧请求覆盖新查询结果
- **FR-014**: 所有产生副作用的请求必须防止重复点击，并按后端契约携带稳定的幂等标识
- **FR-015**: 写操作失败时必须区分可重试和不可重试错误；可恢复表单不得因网络失败丢失用户输入
- **FR-016**: 金额必须以后端整数分为唯一数据来源并转换为元展示，禁止使用浮点计算生成业务金额
- **FR-017**: 消费相关页面必须使用 009 定义的 `*AmountCent`、账单状态和最新列表/明细语义，不再消费旧贡献值字段
- **FR-018**: 绩效页面必须区分当前月预估和历史已确认结果，未审核月份不得展示为已确认
- **FR-019**: 客户、组织、绩效和其他受限数据必须服从后端授权范围；前端隐藏入口不能替代服务端鉴权
- **FR-020**: 手机号、身份证号、医保账户等敏感数据在所有响应展示、缓存、日志、错误和测试数据中必须保持脱敏
- **FR-021**: 客户列表、详情、编辑、跟进、绑定记录和绑定结果必须使用真实后端状态，并覆盖成功、待匹配、处理中、失败和权限拒绝
- **FR-022**: 用户资料、头像、资质文件和反馈附件必须通过后端授权的上传流程处理，客户端不得持有云存储密钥
- **FR-023**: 登录用户切换或退出时必须清理上一账户的业务缓存、页面快照和敏感输入
- **FR-024**: 未知枚举、缺少必填字段或响应格式错误必须进入受控失败状态，禁止使用 Mock 或默认业务成功值掩盖契约错误
- **FR-025**: 每个接入接口必须具备契约测试或等价的响应适配测试；每个 P1 用户故事必须具备覆盖成功与关键失败路径的集成测试
- **FR-026**: 联调必须保留现有已确认 UI、导航和业务校验；除为真实数据状态所必需的调整外，不进行页面重设计
- **FR-027**: 后端缺少接口或响应与已确认契约不一致时，必须记录差异并先更新契约或后端，禁止在页面中加入不可追踪的临时兼容逻辑
- **FR-028**: 生产代码不得包含真实客户数据、测试账号密码、访问令牌、微信密钥、云存储密钥或哈尔滨接口签名密钥

### Key Entities *(include if feature involves data)*

- **客户端会话 (Client Session)**: 当前登录账户的访问凭证、过期信息、用户身份、组织角色与权限；与 Demo Session 隔离
- **API 契约映射 (API Contract Mapping)**: 页面动作与后端端点、字段、枚举、分页、幂等和错误码之间的可追踪关系
- **请求上下文 (Request Context)**: 一次请求所需的环境地址、授权信息、幂等标识、查询条件和可安全记录的请求标识
- **客户视图 (Customer View)**: 客户基本信息、绑定、服务记录、跟进及消费记录的脱敏客户端表示
- **消费视图 (Consumption View)**: 以后端整数分和账单状态为来源的概览、趋势、列表与明细
- **绩效视图 (Performance View)**: 当前月预估与历史已确认核算结果的客户端表示
- **上传资产 (Uploaded Asset)**: 由后端授权和管理的头像、资质或反馈附件引用，不包含客户端云存储密钥

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: P1 用户故事中的登录、工作台、客户绑定、消费和绩效主链路 100% 使用真实后端数据完成端到端验收
- **SC-002**: 页面—接口—字段矩阵覆盖所有联网页面和用户动作，已知契约冲突解决率为 100%
- **SC-003**: 体验与生产构建中，业务页面对 `mock/` 数据的运行时读取为 0，后端失败时 Mock 回退次数为 0
- **SC-004**: 访问令牌过期场景中，有效刷新令牌可恢复原请求；无效刷新令牌 100% 清理会话并回到登录页，不发生刷新循环
- **SC-005**: 核心列表在连续分页、切换筛选和快速搜索测试中无重复项、无旧响应覆盖，符合后端返回范围
- **SC-006**: 快速重复点击和超时重试测试中，客户绑定、跟进、反馈、资质等副作用操作的重复业务记录数为 0
- **SC-007**: 首页、消费、客户详情和绩效页面对同一账户同一月份的可比金额与后端结果偏差为 0
- **SC-008**: 手机号、身份证号、医保账户、令牌和密钥在页面、日志、错误信息和测试快照中的明文泄露数为 0
- **SC-009**: 401、403、404、业务冲突、超时、断网、500 和畸形响应均有可复现验收结果，页面不会无限加载或伪装成功
- **SC-010**: 本特性新增和修改代码的自动化测试全部通过，且每个接入端点至少有一项契约或响应适配验证
- **SC-011**: 用户从账户 A 退出并登录账户 B 后，所有已验收页面展示账户 A 数据的数量为 0
- **SC-012**: 不改变已确认 UI 主结构的前提下，所有接入页面均可在微信开发者工具及至少一台真机完成主链路验收

## Assumptions

- 北京后端 `/api/v1` 已实现大部分业务端点，并遵守统一响应格式；联调发现的契约缺口允许在本特性中进行最小兼容修正
- 手机号密码登录与微信绑定以 004 为准；用户可能先由管理后台创建，再在小程序完成微信绑定
- 消费金额口径以 009 为准，金额传输单位为整数分，客户端只负责格式化展示
- 绩效预估和已确认结果以 008 为准，核算与审核逻辑仍由后端负责
- 客户敏感数据遵循 Constitution 2.0 的前后台统一脱敏规则，不因页面编辑需求返回明文
- 已确认 UI、现有页面路由和页面级表单校验继续复用；真实数据字段差异通过明确的适配层解决
- 本地开发允许使用 `127.0.0.1` 并在微信开发者工具关闭合法域名校验；体验和生产使用已备案 HTTPS API 域名
- 真实联调需要准备不含真实患者敏感信息的测试账户、组织、客户、账单、绩效和资质数据

## Out of Scope

- 重新设计已确认的小程序页面、导航结构或视觉体系
