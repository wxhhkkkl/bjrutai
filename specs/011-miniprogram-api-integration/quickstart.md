# Quickstart: 小程序前后端联调验收

本文用于 `api-link` 分支的前端联调。不要连接生产患者数据，不修改后端逻辑。

## 1. 前置条件

- 微信开发者工具导入 `LuTaiMiniProgram/miniProgram/`。
- 使用 Node 18+ 运行 `node:test`；系统 Node 12 不支持当前测试命令。
- 后端负责人提供可访问的测试环境或在本机启动现有后端。
- 准备以下脱敏测试数据：
  - 已创建、已激活、未绑定微信的普通分销员
  - 已绑定微信的普通分销员
  - 已绑定微信的组织管理员
  - 至少 3 个不同绑定状态的测试客户
  - 至少 2 个月账单与一条已确认绩效结果
- 微信开发者工具本地调试可勾选“不校验合法域名”；体验/生产不得关闭域名校验。

## 2. 联调门禁

在实现前确认 [page-api-matrix.md](contracts/page-api-matrix.md)：

- 只接 READY/ADAPT 项。
- BLOCKED 项不调用危险接口，不用 Mock 替代。
- 浏览器/终端日志不得出现 Token、完整手机号、身份证号或医保账户。

## 4. Scenario A — 手机号登录与微信绑定

1. 清理真实会话存储，不清理 UI Mock 资产。
2. 使用未绑定微信的分销员手机号密码登录。
3. 预期进入微信绑定页，而不是首页。
4. 完成 `wx.login` 绑定，确认 token 对更新并进入首页。
5. 重新启动小程序，验证 session 恢复。
6. 当前已知 `B-002` 可能阻塞组织管理员完整恢复；普通账户应先验证。

## 5. Scenario B — Token 刷新与退出

1. 使用测试方式令 access token 过期，保留有效 refresh token。
2. 并发触发首页和我的页请求。
3. 预期只发生一次 refresh，两组原请求成功恢复。
4. 再使用无效 refresh token，预期清空会话并只跳转一次登录页。
5. 登录后点击退出，确认调用 logout 并清除本地所有账户缓存。

## 6. Scenario C — 首页与我的

1. 登录普通分销员，核对 workbench 客户数、本月绑定、消费金额、待跟进。
2. 核对我的页账户摘要和指标与同一后端数据一致。
3. 登录组织管理员，验证入口门禁；若冷启动缺失 orgRole，记录 B-002，不本地硬编码管理员。
4. 断开后端，页面必须显示错误，不能出现固定“36 个客户”等 Mock 数据。

## 7. Scenario D — 客户列表与详情

1. 客户列表执行全部/待匹配/待跟进筛选、关键字搜索和两页加载。
2. 验证无重复、无旧搜索响应覆盖新结果。
3. 打开本人客户详情并核对脱敏信息和消费汇总。
4. 不验收 B-003 阻塞的子资源和跟进写入，除非矩阵状态已由后端确认更新。
5. 尝试手工构造无权限客户 ID，必须看到 403/无权限且无数据。

## 8. Scenario E — 客户绑定

1. 拉取可选分销员，填写测试客户信息。
2. 记录授权后提交绑定，连续快速点击提交。
3. 预期仅一个有效 requestId，并显示真实状态。
4. 在绑定记录中按状态和关键字查询。
5. 绑定详情/重试受矩阵阻塞时不操作，不使用固定成功页代替。

## 9. Scenario F — 消费与绩效

1. 选择同一分销员和当前月份。
2. 对照 overview、trend、list、workbench 和后端账单总额。
3. 所有金额应为整数分来源、元展示，偏差为 0。
4. 切换月份并快速切换回来，旧响应不得覆盖当前月份。
5. 消费详情 B-004 未解除前不开放点击。
6. 验证当前月绩效为 estimate、历史审核月为 confirmed。

## 10. Scenario G — 隐私、推广与反馈

1. 加载最新协议和当前授权记录。
2. 修改隐私设置并重新进入页面确认后端恢复。
3. 获取推广码；无 qrImageUrl 时显示真实空态，不展示本地假二维码。
4. 选择反馈图片，完成授权上传并提交反馈。
5. 断网提交时保留非敏感表单内容，未知结果重试复用请求 key。

## 11. 生产 Mock 检查

在体验版构建前执行代码扫描：

```bash
rg -n "mock/|foundation-fixtures|getDemoSession|setDemoSession" pages services app.js
```

允许的引用必须有明确开发环境门禁；生产路径直接引用数量必须为 0。关闭后端后，体验版所有业务页面只能显示错误/空态，不能显示演示客户或演示金额。

## 12. 完成标准

- 所有 READY/ADAPT P1 矩阵项完成并通过测试。
- 所有 BLOCKED 项有稳定 ID、负责人和前端受控状态。
- 没有 `backend/` 修改。
- 自动化测试全绿，微信开发者工具无编译错误。
- 至少一台真机完成登录、首页、客户列表、绑定提交、消费和退出主链路。
- 无敏感信息和凭证泄露。
