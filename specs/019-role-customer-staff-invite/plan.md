# Implementation Plan: 患者归属、业务员权限与组织邀请闭环

**Branch**: `feature/user-feedback-20260914` | **Date**: 2026-09-14 | **Spec**: `spec.md`

## Summary

移除首次登录自动挂载默认组织；在会话与后端统一增加有效人员权限；将客户录入改成手机号驱动的待匹配客户；自主注册或手机号快捷登录产生无归属待绑定客户；把推广码定义为客户绑定码并增加患者扫码页。患者扫码绑定时在同一事务内完成微信登录、手机号授权和客户归属，成功后直接进入首页；绑定记录使用统一的“已归属、匹配中、需处理”分组；新增组织管理员业务员加入码；后台新增复用已有账号入组织能力。

## Constitution Check

- TDD：先补充角色、合并、令牌和邀请流程测试，再实现。
- API First：新增接口统一返回现有响应信封，归属人员只由服务端令牌解析。
- Separation：业务规则位于后端，小程序和管理后台仅做展示与表单校验。
- Database Integrity：使用 Alembic 增加手机号索引、客户用户关联与邀请码表；所有响应保持脱敏。
- Simplicity：保留现有 `Distributor` 作为组织人员模型，不引入额外角色框架。

## Implementation Slices

1. 登录身份与有效人员权限。
2. 客户预录入与手机号合并。
3. 客户绑定码及患者扫码页。
4. 自主注册待绑定客户池与后续归属合并。
5. 组织管理员业务员加入码及加入页。
6. 后台复用已有账号入组织与界面文案。
7. 数据库迁移、契约测试、集成测试与前端构建验证。
