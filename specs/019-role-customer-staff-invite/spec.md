# Feature Specification: 患者归属、业务员权限与组织邀请闭环

**Feature Branch**: `feature/user-feedback-20260914`  
**Created**: 2026-09-14  
**Status**: Approved  
**Input**: 患者即客户；推广员即组织管理员；业务员即组织成员。患者扫码归属发码业务员，业务员可预录客户，只有组织人员可使用客户与消费功能，组织管理员可以通过二维码发展业务员，后台可将已有个人账号加入组织并设为管理员。

## Domain Roles

- `User` 是登录身份，不是业务角色。
- 患者存储为 `Customer`，不得因为登录或扫码自动创建组织人员。
- 业务员存储为 `Distributor(org_role=member)`。
- 推广员存储为 `Distributor(org_role=admin)`，同时拥有业务员能力。
- 后台管理员存储为 `AdminAccount`，与小程序组织管理员保持独立。

## User Scenarios & Testing

### User Story 1 - 登录不自动加入组织 (Priority: P0)

新用户通过微信或手机号注册后只获得登录账号。未通过后台或组织邀请加入组织前，不得成为业务员，也不得访问客户和消费能力。

**Acceptance Scenarios**:

1. 新微信用户登录后，系统只创建 `User`，不创建 `Distributor`。
2. 无组织账号的会话返回 `hasBusinessMembership=false`。
3. 无组织账号的小程序仅显示首页、文章与个人资料，隐藏客户和消费标签及入口。
4. 无组织账号直接调用客户、绑定、消费、客户分析接口时返回 403。
5. 已停用人员或停用组织同样不得访问业务接口。

### User Story 2 - 业务员预录入客户并按手机号合并 (Priority: P0)

业务员只需提供客户手机号即可先建立待匹配客户。患者之后扫描同一业务员的客户绑定码并授权相同手机号时，系统补充同一条客户记录，不创建重复账号。

**Acceptance Scenarios**:

1. 业务员提交手机号后，无论儒泰是否即时匹配，均创建或复用待匹配 `Customer` 并将 `BindingRequest.customer_id` 与其关联。
2. 身份证号保持选填，手机号按纯 11 位号码标准化匹配。
3. 同一业务员、同一手机号的重复待处理提交被阻止。
4. 同一手机号已归属其他业务员时，不自动转移，返回明确冲突提示。
5. 儒泰匹配成功时只更新既有客户，不另外创建客户。

### User Story 3 - 患者扫描客户绑定码 (Priority: P0)

业务员分享客户绑定码。患者扫码进入专用页面、同意数据授权并授权手机号后，客户直接归属发码业务员。

**Acceptance Scenarios**:

1. 客户绑定码令牌只能在后端解析为发码业务员，客户端不能指定归属人员。
2. 有效令牌返回发码业务员的脱敏展示信息。
3. 患者授权手机号后，后端按手机号创建或合并客户并记录同意凭据。
4. 过期、停用、所属人员停用或所属组织停用的令牌不可使用。
5. 同一患者重复扫码保持幂等；跨业务员冲突不自动转移。

### User Story 4 - 组织管理员邀请业务员 (Priority: P1)

组织管理员可以生成有效期内可多人使用、可随时撤销和刷新的业务员加入码。新人扫码填写姓名并授权手机号后，以普通业务员身份加入管理员所在组织。

**Acceptance Scenarios**:

1. 只有有效组织的 `org_role=admin` 可生成、查看、刷新或撤销加入码。
2. 普通业务员调用加入码管理接口返回 403，小程序不显示入口。
3. 新手机号扫码后创建 `User` 与 `Distributor(member)`。
4. 已有但尚未加入组织的账号扫码后复用原 `User` 并创建 `Distributor(member)`。
5. 已属于其他组织的账号不能通过扫码静默迁移。

### User Story 5 - 后台将已有账号加入组织 (Priority: P1)

后台管理员可以按手机号搜索尚未加入组织的账号，将其加入指定组织，再按现有权限规则设置为组织管理员。

**Acceptance Scenarios**:

1. 人员新建时手机号已存在且未加入组织，系统复用账号而不是报“手机号已存在”。
2. 已属于组织的账号不能重复创建人员。
3. 后台页面明确显示“复用已有账号”结果，并继续支持设置组织管理员。

## Functional Requirements

- **FR-001**: 首次登录和自主注册 MUST NOT 自动创建 `Distributor`。
- **FR-002**: 会话 MUST 返回业务成员状态、组织角色、人员状态和组织状态。
- **FR-003**: 客户/绑定/消费相关后端接口 MUST 校验有效组织人员；组织邀请接口 MUST 额外校验组织管理员。
- **FR-004**: `Customer` MUST 保存标准化手机号，并可选关联患者 `User`。
- **FR-005**: 客户预录入 MUST 从首次提交开始创建或复用 `Customer`。
- **FR-006**: 同一手机号跨业务员冲突 MUST NOT 自动改变客户归属。
- **FR-007**: 客户绑定码与业务员加入码 MUST 使用不同的数据模型和令牌。
- **FR-008**: 客户绑定码的分享路径 MUST 指向患者绑定页。
- **FR-009**: 业务员加入后默认角色 MUST 为 `member`。
- **FR-010**: 后台 MUST 能复用尚未加入组织的已有账号。
- **FR-011**: 手机号、身份证等敏感信息在响应中 MUST 脱敏。

## Assumptions

- 每个 `User` 当前最多关联一个 `Distributor`，即一个人员只能属于一个组织。
- 延续现有规则：每个组织最多一名组织管理员。
- 业务员加入码默认有效 7 天，在有效期内可多人使用，管理员可以刷新或撤销。
- 扫描客户绑定码立即建立本地客户归属；儒泰匹配状态单独记录，允许异步完成。
