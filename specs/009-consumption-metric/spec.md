# Feature Specification: 业绩贡献口径统一为消费金额（移除业绩贡献值体系）

**Feature Branch**: `009-consumption-metric`  
**Created**: 2026-08-06  
**Status**: Draft  
**Input**: User description: "「业绩贡献」不应再作为独立的贡献值体系存在，全系统统一以消费金额（绑定客户账单实付金额）作为业绩口径；移除贡献记录/贡献系数/贡献结算等配套能力，存量历史数据需平滑迁移。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理后台：业绩展示统一为消费金额 (Priority: P1)

管理员在管理后台看到的「业绩」数据（消费业绩页、工作台、客户详情、组织绩效、报表）全部按**消费金额**口径展示：本月/累计消费金额、月度趋势、组织/个人消费排名、最新消费明细、客户消费记录，单位统一为元。同一口径（绑定客户账单实付金额求和）应用于全后台。

**Why this priority**: 管理后台是业绩数据的源头与核对基准，口径统一是本迭代的核心价值，属 P1。

**Independent Test**: 进入消费业绩页 → 看到本月/累计消费金额与月度趋势 → 查看工作台「本月消费」与客户详情「消费记录」 → 各处数字与按账单实付金额手算结果一致。

**Acceptance Scenarios**:

1. **Given** 管理员进入消费业绩页, **When** 页面加载, **Then** 展示本月/累计消费金额（¥），月度趋势、组织/个人排名、最新消费明细均按消费金额统计
2. **Given** 工作台首页, **When** 查看指标, **Then** 显示「本月消费」（¥），不再显示「本月业绩（分）」
3. **Given** 客户详情, **When** 查看, **Then** 展示该客户本月/累计消费金额与「消费记录」账单列表
4. **Given** 任一业绩数字, **When** 与账单实付金额核对, **Then** 结果一致（排除退款/取消，部分退款全额计入）

---

### User Story 2 - 小程序：贡献展示统一为消费金额 (Priority: P1)

小程序各入口的「贡献值（分）/已结算/待结算」统一改为「消费金额（¥）/已支付/待支付」：本人贡献明细页、首页「我的消费」、组织绩效页的成员/下级组织消费金额。小程序与管理后台同口径，同一分销员在两端的消费金额一致。

**Why this priority**: 小程序是推广员查看业绩的出口，必须与管理后台同口径，属 P1。

**Independent Test**: 打开小程序贡献明细页 → 看到「本月消费 ¥…」→ 明细状态为「已支付/待支付」→ 与后台同一分销员的消费金额一致。

**Acceptance Scenarios**:

1. **Given** 推广员打开贡献明细页, **When** 查看, **Then** 展示「本月消费」金额（¥），明细状态为「已支付/待支付」
2. **Given** 首页, **When** 查看, **Then** 展示「我的消费 / 本月消费金额」，不再出现「贡献值 / 分」
3. **Given** 组织管理员打开组织绩效页, **When** 查看, **Then** 成员与下级组织均展示「本月消费 / 累计消费」（¥）
4. **Given** 同一分销员, **When** 小程序与后台数据核对, **Then** 消费金额一致

---

### User Story 3 - 存量数据迁移与贡献体系移除 (Priority: P1)

一次性迁移：存量 `contribution_records` 中**无账单且贡献值 > 0** 的记录（手工/团队记录）按数值合成为消费账单（生成「历史消费」合成客户），保证如「测试分销 150」等历史数据在新口径下仍可见；随后删除贡献记录/贡献结算日志/贡献系数三张表及对应的模型、服务、接口能力。

**Why this priority**: 迁移是删除贡献体系的前提，缺失则历史业绩不可追溯，属 P1。

**Independent Test**: 迁移前备份 → 执行数据库升级 → 存量贡献记录在消费口径下仍可见（金额一致）→ 三张表已删除 → 全端无贡献体系残留。

**Acceptance Scenarios**:

1. **Given** 存量存在无账单的贡献记录, **When** 执行迁移, **Then** 生成对应消费账单（含「历史消费」合成客户），金额与贡献值一致
2. **Given** 迁移完成, **When** 检查数据库, **Then** 贡献记录/贡献结算日志/贡献系数三张表已删除
3. **Given** 迁移后, **When** 运行后端测试套件, **Then** 全绿，代码中无贡献记录/贡献系数引用残留
4. **Given** 迁移为破坏性, **When** 执行前, **Then** 需备份数据库（文档明示，回退仅重建空表）

---

### Edge Cases

- 无账单的手工/团队贡献记录：迁移时按数值合成账单（贡献值 > 0 且状态非已冲正/已取消）
- 迁移前已有账单的贡献记录：不合成（原账单即口径来源）
- 退款/取消账单：消费统计自动排除
- 部分退款（PARTIALLY_REFUNDED）：按全额计入（与绩效计算一致）
- 无任何账单的组织/人员：消费金额为 0 或空态
- 跨月账单：按账单交易时间归属月份
- 分销员无绑定客户：消费金额为 0
- 迁移中途失败：先备份；回退时清理合成数据并重建空表（原贡献记录不可恢复）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 全系统「业绩贡献」必须统一为「消费金额」口径：某分销员周期内其绑定客户的已支付账单实付金额之和（排除退款/取消；部分退款按全额计入）
- **FR-002**: 必须提供共享的口径计算能力（按分销员聚合、按客户聚合），全系统唯一口径实现，禁止各处重复查询
- **FR-003**: 必须移除贡献记录体系：贡献记录表、对应模型、贡献计算服务、贡献相关数据模型及分销员上的贡献关联
- **FR-004**: 必须移除贡献系数：贡献系数表、对应模型、系数查询/更新逻辑
- **FR-005**: 必须移除旧的贡献结算批处理能力，月度结算任务直接调用绩效核算
- **FR-006**: 必须提供一次性迁移：存量无账单且贡献值 > 0 的记录合成为消费账单（含「历史消费」合成客户）；删除贡献相关三张表
- **FR-007**: 各 API 响应中业绩数值字段必须从贡献值改为消费金额（整数分）；保留既有业绩数据访问路径
- **FR-008**: 管理后台（消费业绩页/工作台/客户详情/组织绩效）与小程序（贡献明细页/首页/组织绩效页）的展示必须从「贡献值（分）」切换为「消费金额（元）」
- **FR-009**: 退款/冲正处理由账单状态过滤天然覆盖（消费口径自动排除退款），不得再保留贡献冲正记录逻辑
- **FR-010**: 迁移脚本的删除操作必须在文档中明示为破坏性（升级前备份），回退提供尽力恢复（清理合成数据 + 重建空表）

### Key Entities *(include if feature involves data)*

- **消费金额 (Consumption Amount)**: 某分销员/客户在周期内的消费口径金额（整数分），由共享口径计算能力得出。
- **账单 (Bill)**: 消费口径的唯一数据来源；取实付金额（分），按交易状态过滤退款/取消。
- **合成客户 (Synthetic Customer)**: 迁移时按分销员惰性创建的名称为「历史消费」的客户，用于挂接合成账单。
- **合成账单 (Synthetic Bill)**: 迁移时由无账单的贡献记录生成的账单，携带可追溯的标识。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全系统任一「业绩」数字均等于同一口径（账单实付金额求和）计算的消费金额，跨页面/跨端核对偏差为 0
- **SC-002**: 消费金额统计 100% 排除退款/取消账单（自动化测试覆盖）
- **SC-003**: 迁移执行后，存量贡献记录以消费账单形式可见，金额与迁移前一致
- **SC-004**: 迁移执行后代码中无贡献记录/贡献系数/旧贡献结算引用残留，后端测试套件全绿
- **SC-005**: 管理后台与小程序不再展示「贡献值/分」，统一展示「消费金额/元」
- **SC-006**: 看板/排名/趋势仍为实时聚合，中小数据量下 2 秒内返回（与既有性能目标一致）

## Assumptions

- 业绩贡献与消费金额口径统一后，绩效计算仍按绩效规则计算提成，计算逻辑不受本迭代影响
- 业绩数据访问路径与部分文件/接口命名保留 `contribution` 兼容名，仅语义变为消费金额，避免前端大面积改路由
- 迁移为破坏性：升级前必须备份数据库；回退无法恢复原始贡献记录（仅重建空表）
- 本迭代不含新页面开发，仅对既有页面（管理后台消费业绩页/工作台/客户详情/组织绩效、小程序贡献明细/首页/组织绩效）做口径与文案切换
- 小程序底部标签文案由「贡献」改为「消费」，标签项标识与页面/文件命名保留 `contribution` 兼容名
