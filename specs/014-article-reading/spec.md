# Feature Specification: 小程序文章资讯与阅读

**Feature Branch**: `014-article-reading`  
**Created**: 2026-08-10  
**Status**: Draft  
**Input**: User description: "分析后台管理系统的文章管理模块；后台功能已有，但小程序没有对应入口。在首页合适位置和‘我的’页面服务宫格指定位置增加入口，对接后台接口，实现文章查看与阅读。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从首页发现并阅读最新文章 (Priority: P1)

已登录用户进入首页后，可在“业务概览”之后、通知与最近绑定之前看到“文章资讯”区域。该区域展示最新发布文章的标题、摘要、封面及发布时间；用户可以直接打开某篇文章，也可以进入全部文章列表。

**Why this priority**: 首页是访问频率最高的页面，展示最新文章能够让后台发布的内容真正触达用户，也是文章能力产生业务价值的最短路径。

**Independent Test**: 后台准备至少 3 篇已发布文章和 1 篇草稿。用户进入首页后仅看到最新的已发布文章，点击任一文章可打开对应详情，点击“查看全部”可进入文章列表。

**Acceptance Scenarios**:

1. **Given** 后台存在已发布文章，**When** 用户进入首页且首页业务数据加载成功，**Then** “文章资讯”区域展示最多 3 篇最新发布文章，并按发布时间从新到旧排列。
2. **Given** 首页展示了一篇文章，**When** 用户点击该文章，**Then** 系统打开对应文章详情，标题和正文与后台发布内容一致。
3. **Given** 首页文章数量超过展示上限，**When** 用户点击“查看全部”，**Then** 系统进入文章列表并可继续浏览其余已发布文章。
4. **Given** 暂无已发布文章，**When** 用户进入首页，**Then** 首页不展示虚构文章，也不因文章为空影响工作台、快捷服务和业务概览的正常使用。
5. **Given** 文章数据加载失败，**When** 首页其他业务数据可正常获取，**Then** 首页核心内容保持可用，文章区域显示可理解的失败状态或仍提供进入文章列表的入口。

---

### User Story 2 - 从“我的”页面进入文章中心 (Priority: P1)

已登录用户在“我的—我的服务”宫格中，可从截图标注的空白服务位置进入“文章资讯”。入口与现有推广码、绑定记录和消费明细保持一致的视觉与交互层级，并面向所有已激活的小程序业务用户显示。

**Why this priority**: “我的”页面提供稳定的功能入口，不依赖首页是否有最新内容，使用户可以随时主动查找和阅读历史文章。

**Independent Test**: 使用普通已激活用户进入“我的”页面，确认原宫格空位显示文章入口；点击后进入文章列表。再使用组织管理员账号验证入口仍可使用且既有管理员专属入口不受影响。

**Acceptance Scenarios**:

1. **Given** 普通已激活用户进入“我的”页面，**When** 页面加载成功，**Then** “我的服务”宫格原空白位置显示“文章资讯”入口和简短说明。
2. **Given** 用户点击“文章资讯”入口，**When** 导航成功，**Then** 系统打开文章列表页，而不是占位页或后台管理页。
3. **Given** 用户是组织管理员，**When** 查看“我的服务”，**Then** 文章入口与既有组织业绩入口同时可用，宫格顺序稳定且无重叠、截断或不可点击区域。

---

### User Story 3 - 浏览文章列表并加载更多 (Priority: P1)

用户在文章列表中查看所有已发布文章。列表按发布时间从新到旧排列，展示封面、标题、摘要、分类和发布时间；文章较多时可以连续加载下一批内容，并能通过下拉刷新回到最新结果。

**Why this priority**: 完整列表是从入口到阅读详情之间的核心浏览能力，确保用户不仅能看到首页推荐的少量文章。

**Independent Test**: 准备超过一页的已发布文章以及草稿、已下架文章，验证首屏、连续加载、刷新、空状态和错误重试；全程不得展示未发布内容，不得出现重复或遗漏。

**Acceptance Scenarios**:

1. **Given** 存在多篇已发布文章，**When** 用户打开文章列表，**Then** 列表按发布时间倒序展示封面、标题、摘要、分类和发布时间。
2. **Given** 文章数量超过单次加载数量，**When** 用户滚动到底部或触发加载更多，**Then** 系统追加下一批文章，不覆盖已显示内容，也不出现重复文章。
3. **Given** 用户已加载多批文章，**When** 用户执行下拉刷新，**Then** 列表重新从最新文章开始展示，并清除旧分页状态。
4. **Given** 后台存在草稿或已下架文章，**When** 用户浏览列表，**Then** 这些文章不会出现在任何列表结果中。
5. **Given** 没有已发布文章，**When** 用户打开列表，**Then** 页面展示明确空状态，不显示模拟数据。
6. **Given** 首次加载或加载更多失败，**When** 页面提示错误，**Then** 用户可重试；已成功展示的文章不会因后续分页失败而丢失。

---

### User Story 4 - 阅读文章富文本详情 (Priority: P1)

用户打开文章后，可以阅读标题、封面、分类、作者、发布时间、浏览量以及后台编辑的图文正文。正文中的段落、标题、列表、强调文本和图片应保持清晰、适合手机屏幕阅读；用户可使用页面返回操作回到原列表位置。

**Why this priority**: 详情阅读是本功能的最终用户价值，必须准确、安全地呈现后台已发布内容。

**Independent Test**: 发布一篇包含多级标题、段落、列表、粗体、链接文本及多张不同尺寸图片的文章，从首页和文章列表分别进入详情，验证内容、排版、图片适配、返回行为及阅读量变化。

**Acceptance Scenarios**:

1. **Given** 用户打开一篇仍处于已发布状态的文章，**When** 详情加载成功，**Then** 页面完整展示文章元信息和后台发布的图文正文。
2. **Given** 正文包含宽图或长图，**When** 页面渲染内容，**Then** 图片不超出屏幕宽度，不引起整页横向滚动，并保持可辨识比例。
3. **Given** 正文包含不受支持或具有主动执行能力的内容，**When** 页面渲染文章，**Then** 系统不得执行脚本、事件或嵌入式程序，受支持的安全文本和图片内容仍可阅读。
4. **Given** 用户成功打开文章详情，**When** 后端记录本次查看，**Then** 文章浏览量增加一次；页面生命周期中的重复显示不得主动重复请求详情。
5. **Given** 用户从文章列表进入详情，**When** 用户返回，**Then** 回到原文章列表，并尽量保持原有已加载内容与阅读位置。
6. **Given** 文章在用户点击前已下架或被删除，**When** 用户请求详情，**Then** 页面提示“文章已下架或不存在”，不展示旧缓存正文，并允许返回文章列表。
7. **Given** 详情请求失败，**When** 用户点击重试，**Then** 系统重新请求当前文章；成功后展示正文，失败时不显示另一篇文章或残留内容。

### Edge Cases

- 首页文章请求慢于工作台请求：文章区域不得阻塞或覆盖已经成功加载的首页核心数据。
- 发布文章缺少封面、摘要、分类、作者或发布时间：页面使用统一的缺省展示或隐藏对应非必填字段，标题和正文仍可正常阅读。
- 标题或摘要超长：列表中按既定行数截断，详情中完整显示标题，不能挤压其他操作区域。
- 正文为空：详情展示“暂无正文内容”的明确状态，不出现空白页面。
- 正文图片地址失效或域名不允许加载：保留正文结构并显示图片加载失败占位，不导致整篇文章不可读。
- 列表翻页期间后台新增、下架或重新发布文章：客户端遵循服务端游标，不无限加载、不重复追加同一文章；刷新后以最新发布状态为准。
- 用户快速重复点击文章：只进入一个详情页面，避免重复页面堆叠和重复阅读计数请求。
- 用户在详情加载期间返回：迟到响应不得更新已离开的页面或污染下一次打开的文章。
- 接口返回格式缺失、文章编号无效或未知字段：页面进入受控错误状态，不使用模拟文章补齐。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 小程序 MUST 在首页“业务概览”之后提供“文章资讯”区域，并在不影响首页核心业务加载的前提下展示最多 3 篇最新发布文章。
- **FR-002**: 首页文章区域 MUST 支持直接打开文章详情，并提供进入完整文章列表的入口。
- **FR-003**: 小程序 MUST 在“我的—我的服务”宫格的用户指定位置新增“文章资讯”入口；入口必须适用于普通已激活用户和组织管理员。
- **FR-004**: 两个入口 MUST 导向同一套文章列表与详情阅读能力，不得分别维护不同文章数据或模拟数据。
- **FR-005**: 小程序 MUST 通过现有后端公开文章服务获取数据，不得直连数据库、管理端接口或云存储管理凭证。
- **FR-006**: 小程序 MUST 仅展示状态为已发布的文章；草稿和已下架文章不得通过首页、列表或详情被用户读取。
- **FR-007**: 文章列表 MUST 按发布时间从新到旧排列，并展示文章标识、标题、摘要、封面、分类和发布时间；作者与浏览量可在有值时展示。
- **FR-008**: 文章列表 MUST 支持服务端游标分页、加载更多和刷新；连续分页不得重复、遗漏或覆盖已成功加载的文章。
- **FR-009**: 文章列表 MUST 提供加载中、成功、空数据、首次加载失败、分页失败和可重试状态，且不得回退到模拟文章。
- **FR-010**: 文章详情 MUST 展示标题、正文及可用的封面、摘要、分类、标签、作者、发布时间和浏览量信息。
- **FR-011**: 文章正文 MUST 支持后台现有富文本内容的安全阅读展示，包括段落、标题、列表、强调文本和图片；不得执行脚本、事件处理器或嵌入式程序。
- **FR-012**: 正文和封面图片 MUST 适配移动端宽度；加载失败时不得阻断其他正文内容的阅读。
- **FR-013**: 成功获取文章详情后 MUST 使用服务端返回的最新浏览量；客户端不得自行计算或伪造阅读次数。
- **FR-014**: 页面 MUST 防止快速重复点击产生重复详情页面，并避免因页面重复显示主动重复请求同一详情。
- **FR-015**: 文章不存在、已下架、请求超时、网络失败和响应格式错误 MUST 显示可区分的受控状态，并提供适用的返回或重试操作。
- **FR-016**: 从列表返回时 SHOULD 保持已经加载的列表内容和用户阅读位置，避免无必要地重新请求首屏。
- **FR-017**: 首页文章模块失败 MUST 与工作台核心状态隔离；文章加载失败不得将整个首页置为失败状态。
- **FR-018**: 文章入口和阅读页面 MUST 延续现有小程序视觉体系、导航安全区、触控反馈、字体层级和底部安全区域规则。
- **FR-019**: 后端现有文章发布、下架、排序、分页和浏览量语义 MUST 保持为文章数据的唯一事实来源；本功能不在小程序复制文章状态判断逻辑。
- **FR-020**: 本功能新增的数据适配、分页、导航和错误状态 MUST 具备自动化测试，覆盖正常结果、空结果、分页追加、详情不存在和格式异常。

### Key Entities

- **文章 (Article)**: 后台创建并发布的可阅读内容，包含唯一标识、标题、摘要、富文本正文、封面、分类、标签、作者、发布状态、发布时间和浏览量。小程序只读取已发布文章。
- **文章列表项 (Article List Item)**: 用于首页和文章列表的轻量展示信息，包含文章标识、标题、摘要、封面、分类、作者、发布时间和浏览量，不包含完整正文。
- **文章详情 (Article Detail)**: 用户打开文章后展示的完整内容，包含列表信息及安全可渲染的富文本正文。
- **文章分页游标 (Article Cursor)**: 服务端返回的下一批文章定位信息；客户端仅保存并回传，不自行推导排序位置。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在正常网络条件下，用户从首页或“我的”入口进入文章列表，并打开任一已发布文章完成阅读的主链路可在 3 次点击内完成。
- **SC-002**: 首页文章区域、文章列表和详情中展示草稿或已下架文章的数量为 0。
- **SC-003**: 使用至少 50 篇验收文章连续加载全部分页时，重复文章数为 0，已发布文章遗漏数为 0。
- **SC-004**: 在正常网络条件下，95% 的文章列表首屏和文章详情在 2 秒内出现可阅读内容或明确状态反馈。
- **SC-005**: 包含段落、标题、列表、强调文本和不同尺寸图片的代表性文章，在主流 iOS 与 Android 微信环境中的正文可读率达到 100%，页面无横向溢出。
- **SC-006**: 首页文章接口超时、失败或返回空数据时，首页工作台、快捷服务和业务概览仍可正常使用，受影响的核心首页模块数量为 0。
- **SC-007**: 对无效、已删除或已下架文章地址进行验收时，旧正文泄露数量为 0，所有场景均给出明确不可用提示。
- **SC-008**: 本功能新增自动化测试全部通过，覆盖的 P1 主链路和关键异常场景通过率为 100%。

## Assumptions

- 用户侧功能名称统一采用“文章资讯”；若后续产品确认使用“健康资讯”“内容中心”等名称，只调整展示文案，不改变数据和导航范围。
- 首页文章区域位于“业务概览”之后、最新通知与最近绑定之前，最多展示 3 篇最新文章；这是在不改变首页核心业务层级前提下对“合适位置”的默认解释。
- “我的”页面入口放入截图标注的服务宫格空位。普通用户形成完整的 2×2 服务宫格；组织管理员保留其专属“组织业绩”入口，文章入口按现有宫格顺序继续排列。
- 后台现有文章管理、分类、发布和下架功能继续使用；现有公开文章列表与详情服务已满足基本数据契约，本迭代以小程序接入为主，仅允许修复联调发现的契约缺陷。
- 文章正文由获授权的后台管理员维护，但客户端仍按安全内容展示规则处理，不信任或执行正文中的主动代码。
- 文章封面和正文图片在体验、生产环境使用微信允许访问的 HTTPS 域名；合法域名配置与发布环境配置由现有部署流程负责。
- 文章浏览不新增个人阅读历史、收藏状态或用户画像，不持久化用户与文章之间的阅读关系。

## Dependencies

- 后台现有文章管理模块：提供文章创建、编辑、分类、发布和下架能力。
- 后端现有公开文章列表与详情服务：仅返回已发布文章，并提供倒序分页和详情浏览量统计。
- 小程序现有统一请求、会话、导航、页面状态和安全区组件：用于保持与其他业务页面一致的网络、错误和导航行为。

## Out of Scope

- 修改或重做后台文章管理页面、文章编辑器、分类管理及发布审批流程。
- 在小程序中创建、编辑、发布、下架或删除文章。
- 文章收藏、点赞、评论、分享海报、订阅提醒、相关推荐和个人阅读历史。
- 文章全文搜索、分类筛选和标签筛选；现有后端查询能力保留，但本迭代不新增对应小程序交互。
- 离线下载文章、长期缓存正文或在接口失败时回退到模拟文章。
- 支持正文中的脚本、表单、音视频播放器、内嵌网页或其他可执行内容。
