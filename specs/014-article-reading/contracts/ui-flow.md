# UI & Navigation Contract: 小程序文章资讯与阅读

**Feature**: 014-article-reading  
**Visual baseline**: 已确认首页 v4、我的 Tab v2，以及用户提供的当前“我的”页面截图

## 1. 首页“文章资讯”区域

**Placement**: `业务概览`卡片之后，`最新通知`/`最近绑定`之前。

**Structure**:

- 标题行：“文章资讯” + “查看全部 ›”。
- success：最多 3 个文章条目；首条可使用较完整卡片，其余保持紧凑，具体布局在不改变现有页面宽度和圆角体系的前提下实现。
- 每条至少显示标题；摘要、封面、分类、发布时间按数据可用性展示。
- empty：不显示虚构条目；可以隐藏内容区，仅保留稳定“查看全部”入口，或整体收起，验收以不出现大块空白为准。
- recoverable-error：首页不进入全页错误；保留“文章资讯”标题/入口并提供轻量失败提示，不遮挡业务概览。

**Actions**:

- 点击文章：`/pages/article-detail/index?articleId={encodedId}`。
- 点击查看全部：统一 `article-list` action。
- 快速重复点击同一条：只允许一次有效 navigateTo。

## 2. “我的—我的服务”入口

**Placement/order**:

```text
普通用户：
我的推广码     绑定记录
消费明细       文章资讯

组织管理员：
保留“组织业绩”，其余项目按现有 SERVICE_ITEMS 顺序排列；
文章资讯位于消费明细之后，不覆盖任何管理员专属入口。
```

**Copy**:

- Title: `文章资讯`
- Description: `阅读最新内容`
- Icon: 本地文章/文档语义图标，尺寸与现有 service icon 一致。

**Action**: `article-list` → `/pages/articles/index`。

## 3. 文章列表页

**Navigation**: 标准二级页，标题“文章资讯”，使用现有返回组件并适配胶囊和状态栏。

**List item**:

- 封面为固定比例圆角区域；无封面显示低对比度文章占位，不拉伸其他图片。
- 标题最多 2 行，摘要最多 2 行，超出截断。
- 分类与发布时间为次要信息；作者/浏览量有值时才展示。
- 整个卡片为触控区域，满足现有 tap-target 和反馈规范。

**States**:

| State | UI |
|-------|----|
| loading | 页面骨架或现有 loading state |
| success | 列表 + 可选底部加载更多状态 |
| empty | “暂无文章”及简短说明 |
| recoverable-error | 明确错误 + 重试 |
| load-more-error | 保留已加载列表，底部显示“加载失败，点击重试” |
| no-more | 简洁结束提示，不继续请求 |

**Refresh/pagination**:

- 下拉刷新清除 cursor 后请求首屏。
- 触底仅在 `hasMore && !loadingMore` 时请求。
- 从详情返回时不主动刷新，保持页面栈内列表与滚动位置。

## 4. 文章详情页

**Navigation**: 标准二级页，标题可用“文章详情”；正文内不重复显示页面级导航标题。

**Content order**:

1. 文章标题；
2. 分类、作者、发布时间、浏览量等可用元信息；
3. 可选封面；
4. 可选摘要引导；
5. 富文本正文；
6. 底部安全区留白。

**Reading rules**:

- 正文基础字号不低于现有二级页正文标准，行高约 1.7–1.9。
- 标题、段落、列表、引用/强调层级清晰。
- 正文图片 `max-width: 100%`、高度自适应；不得产生页面横向滚动。
- 不执行脚本、事件、表单、iframe 或其他嵌入程序。
- 外链文本本迭代仅按安全富文本能力展示，不承诺点击跳转。

**Failure states**:

- invalid id：不发请求，提示地址无效并返回。
- 404：清空文章对象，显示“文章已下架或不存在”。
- network/server/malformed：清空旧文章，显示重试。
- 图片失败：正文其他内容继续展示。

## 5. Responsive acceptance

- 检查至少 320px 级窄屏和常见 375/390px 级屏幕。
- 首页新区域不遮挡自定义 TabBar，详情底部保留 safe-area。
- 服务宫格在普通用户 2×2、管理员多行场景中保持分隔线和点击区域正确。
- 长标题、无封面、无摘要、无分类、超长正文和宽图均需覆盖。
