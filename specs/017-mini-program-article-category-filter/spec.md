# Feature Specification: 小程序文章分类筛选

**Feature Branch**: `feature/user-feedback-20260914`  
**Created**: 2026-09-14  
**Status**: Ready for implementation  
**Input**: 在小程序“文章资讯”列表页添加按分类筛选文章的功能。

## User Scenarios & Testing

### User Story 1 - 按文章分类浏览 (Priority: P1)

拓展人员进入文章资讯页后，可在“全部”和后台维护的文章分类之间切换，只查看所选分类下已发布的文章。

**Independent Test**: 创建两个分类及各自已发布文章，选择其中一个分类后仅显示该分类文章；选择“全部”后恢复所有已发布文章。

**Acceptance Scenarios**:

1. **Given** 后台已维护文章分类，**When** 用户打开文章资讯页，**Then** 页面显示“全部”和可用分类。
2. **Given** 用户选择一个分类，**When** 列表请求完成，**Then** 仅显示该分类下的已发布文章，分页继续使用当前分类条件。
3. **Given** 所选分类没有已发布文章，**When** 请求完成，**Then** 页面显示“暂无已发布文章”空状态。
4. **Given** 分类列表接口暂时不可用，**When** 用户打开页面，**Then** 页面保留“全部”并正常加载所有文章。

### Edge Cases

- 切换分类时，先前分类的慢响应不得覆盖当前分类结果。
- 分类名称过长时，筛选项横向滚动且不遮挡页面内容。
- 分类接口只返回分类编号和名称，不返回文章内容或用户信息。

## Requirements

- **FR-001**: 小程序文章资讯页必须提供“全部”及后台维护的文章分类筛选项。
- **FR-002**: 小程序选择分类后必须将分类名称作为现有文章列表接口的筛选条件，并在加载更多与下拉刷新中保持该条件。
- **FR-003**: 后端必须提供无需登录、仅返回文章分类编号和名称的公开分类读取接口。
- **FR-004**: 分类列表加载失败不得阻断文章列表的加载或阅读。
- **FR-005**: 分类切换、加载、空数据和网络错误必须沿用文章页现有的中文状态反馈。

## Success Criteria

- **SC-001**: 用户从进入文章资讯页到查看任一分类的文章不超过两次点击。
- **SC-002**: 选择分类后，展示列表中的文章 100% 符合该分类条件。
- **SC-003**: 分类读取失败时，用户仍能查看全部已发布文章。

## Assumptions

- 后台“文章分类”中的名称是文章公共筛选的唯一显示名称。
- 现有文章列表的 `category` 查询参数继续按分类名称筛选，保持接口兼容。
