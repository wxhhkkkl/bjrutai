# Feature Specification: 文章视频上传与小程序点播

**Feature Branch**: `021-article-vod-video`

**Created**: 2026-09-29

**Status**: Ready for planning

**Input**: 用户需求：“管理后台在文章管理新建/编辑文章时上传视频，并在小程序端播放，使用腾讯云点播。”用户确认每篇文章可选上传 1 个视频，展示在正文上方；支持 MP4/MOV、单文件不超过 1 GB；视频沿用文章的公开访问规则。

## Context

管理后台已经支持文章标题、分类、封面、富文本正文、草稿、发布、下架和预览；小程序已支持已发布文章的列表与图文详情。现有文章没有视频字段，详情页没有播放器。此次在现有文章阅读链路中增加可选的腾讯云点播视频，不改变无视频文章的阅读方式。

## User Scenarios & Testing

### User Story 1 - 在新建或编辑文章时上传视频 (Priority: P1)

有文章写入权限的管理员可以在文章表单选择一个本地视频，看到上传进度及处理状态；视频就绪后，可以与文章一起保存。视频作为独立内容展示在正文上方，正文仍可正常编辑。

**Why this priority**: 上传并建立文章与视频的关系，是小程序播放的前提。

**Independent Test**: 新建文章，选择合规视频，等待上传和处理完成，保存草稿并重新打开；视频仍关联该文章，正文和封面未丢失。

**Acceptance Scenarios**:

1. **Given** 管理员打开新建文章表单，**When** 选择合规视频，**Then** 表单立即播放本地所选视频，并显示文件名、上传进度，以及上传完成后的处理状态；云端视频就绪后预览切换到可信播放地址。
2. **Given** 视频已在腾讯云点播处理就绪，**When** 管理员保存文章，**Then** 文章保存视频关联；重新编辑时可看到该视频及其状态。
3. **Given** 管理员重新编辑已有视频的文章，**When** 打开表单，**Then** 使用该视频的可信播放地址预览。
4. **Given** 视频仍在上传或处理中，**When** 管理员保存草稿，**Then** 草稿保留视频关联和真实状态，界面不会把它标成可播放。
5. **Given** 文件类型、大小不符合限制或上传失败，**When** 管理员尝试上传，**Then** 表单说明原因，并允许重新选择文件；失败视频不会成为文章的可播放视频。
5. **Given** 管理员没有文章写入权限，**When** 请求视频上传或绑定操作，**Then** 服务端拒绝，且不会签发上传授权。

---

### User Story 2 - 更换、移除和预览文章视频 (Priority: P1)

管理员在编辑文章时可以更换或移除视频，并在现有预览中检查视频相对于封面、摘要和正文的位置。已发布文章的视频更换需要在新视频就绪后保存，避免读者在处理中看到不可播放内容。

**Why this priority**: 编辑与撤回是文章管理的日常操作，视频变更不能破坏正在阅读的文章。

**Independent Test**: 对一篇已有视频的已发布文章上传替换视频；处理期间小程序继续播放旧视频；新视频就绪并保存后改播新视频；移除后文章仍可阅读图文。

**Acceptance Scenarios**:

1. **Given** 已发布文章关联可播放视频，**When** 管理员上传替换视频但尚未保存，**Then** 小程序仍播放原视频。
2. **Given** 替换视频已就绪，**When** 管理员保存修改，**Then** 小程序下一次加载文章详情时播放新视频，文章其他内容保持原样。
3. **Given** 已发布文章关联视频，**When** 管理员移除视频并保存，**Then** 小程序下一次加载详情时不再显示播放器，图文仍可阅读。
4. **Given** 管理员预览含视频文章，**When** 预览打开，**Then** 视频位于正文上方，可检查封面、摘要、视频和正文的展示顺序。
5. **Given** 两名管理员同时编辑同一文章，**When** 后提交者保存过期版本，**Then** 沿用现有版本冲突规则拒绝覆盖，包括视频关联变更。

---

### User Story 3 - 在小程序文章详情播放视频 (Priority: P1)

读者打开已发布文章后，可在正文上方看到视频封面和播放入口，点击后在文章详情中播放；阅读正文、图片预览和评论不受影响。

**Why this priority**: 这是读者侧的核心价值，也是上传功能最终应交付的结果。

**Independent Test**: 发布一篇包含封面、摘要、视频、富文本和评论的文章，在 iOS、Android 微信小程序中打开并播放，验证页面顺序、进度控制、暂停及失败提示。

**Acceptance Scenarios**:

1. **Given** 文章已发布且视频就绪，**When** 读者打开详情，**Then** 在封面和摘要之后、正文之前看到视频区域；视频不会自动播放。
2. **Given** 视频区域可用，**When** 读者点击播放，**Then** 可在小程序中播放、暂停、拖动进度并进入全屏。
3. **Given** 读者离开详情或小程序进入后台，**When** 页面不再可见，**Then** 视频停止或暂停，不继续产生后台声音。
4. **Given** 视频加载或播放失败，**When** 播放器报告错误，**Then** 页面给出可理解的提示和重试入口，标题与图文仍可阅读。
5. **Given** 文章没有视频，**When** 读者打开详情，**Then** 页面不显示空播放器，原有图文和评论布局保持可用。
6. **Given** 文章是草稿、已下架或已删除，**When** 小程序请求文章详情，**Then** 沿用现有文章可见性规则，不返回文章或视频播放信息。

### Edge Cases

- 上传中断、浏览器关闭、上传授权过期或点播服务暂时不可用时，显示准确状态；重新上传不会生成两个有效文章视频。
- 点播上传完成但转码或处理失败时，视频保持失败状态，管理员可移除或重新上传；不能被标记为就绪。
- 视频处理通知重复、延迟或乱序到达时，以服务端核实的最终状态为准，不把旧视频重新绑定到文章。
- 管理员上传视频后取消编辑，或移除、更换视频后留下无文章引用的媒资时，系统应有可追踪的清理机制，且不能删除仍被文章使用的视频。
- 已发布文章的视频在发布后被云端删除、播放地址失效或域名不可用时，小程序保留文章内容并提示视频暂不可用。
- 视频竖屏、横屏以及封面缺失时，播放器保持合适比例，不造成页面横向溢出。
- 视频仅在正文上方作为独立区块呈现；历史富文本中的不受支持媒体标签仍遵循现有安全过滤规则。

## Requirements

### Functional Requirements

- **FR-001**: 管理后台 MUST 在文章新建和编辑表单提供一个可选视频位，每篇文章最多关联 1 个视频；视频与现有标题、分类、封面、摘要和正文可同时存在。
- **FR-002**: 管理员 MUST 能选择本地 MP4 或 MOV 视频上传；单文件上限为 1 GB。前端即时提示限制，服务端对上传授权及最终绑定执行同等校验。
- **FR-003**: 视频 MUST 上传到腾讯云点播；视频文件不得保存到现有图片 COS 路径，文章正文也不得以任意视频 URL 或可执行嵌入代码代替正式视频关联。
- **FR-004**: 视频上传授权 MUST 由后端在核验 `articles.write` 权限后签发；长期云密钥只保存在服务端配置中，不得进入管理端或小程序包。
- **FR-005**: 管理端 MUST 显示上传进度、上传中、处理中、就绪和失败状态，并为可恢复失败提供重新选择或重试操作。首次选择视频后立即使用本地文件预览；云端就绪后及重新编辑已有视频时使用可信播放地址；切换、移除或关闭时释放本地预览资源。
- **FR-006**: 后端 MUST 持久保存视频的点播媒资标识、所属文章或待绑定状态、处理状态及可用播放信息；只有确认属于本应用且上传完成的媒资才可绑定文章。
- **FR-007**: 后端 MUST 以可信的点播状态确认视频可播放；重复或延迟的处理通知不得导致状态倒退或覆盖较新的文章视频关联。
- **FR-008**: 草稿 MAY 在视频处理中保存，但含视频的文章 MUST 仅在关联视频就绪后才能发布；发布失败提示须说明视频尚未就绪或处理失败。
- **FR-009**: 已发布文章更换视频时，原视频 MUST 持续对读者可用，直到新视频就绪且管理员成功保存；移除视频仅在保存成功后对读者生效。
- **FR-010**: 文章视频变更 MUST 遵循现有文章版本控制、后台权限与统一错误响应规则。
- **FR-011**: 文章预览 MUST 展示视频区块，并保持与小程序文章详情一致的内容顺序；无视频文章预览不显示空区块。
- **FR-012**: 已发布文章详情接口 MUST 以向后兼容方式返回可播放视频所需的信息；草稿、已下架或未就绪的视频不得作为可播放内容返回给小程序。
- **FR-013**: 小程序 MUST 在文章详情正文上方提供视频播放器，支持播放、暂停、进度控制和全屏；默认不自动播放。
- **FR-014**: 小程序 MUST 在离开文章详情或页面不可见时暂停视频，并在播放失败时提供局部错误提示与重试操作，不影响图文阅读。
- **FR-015**: 视频播放地址 MUST 使用小程序可访问的 HTTPS 点播分发地址；点播应用、播放域名及相关云配置须由部署环境配置，不得硬编码密钥。
- **FR-016**: 无视频的存量文章 MUST 保持现有列表、详情、分享、图片预览与评论行为。
- **FR-017**: 未绑定或已移除的视频媒资 MUST 可追踪并纳入清理流程；清理前 MUST 确认没有有效文章引用，避免误删仍在播放的视频。
- **FR-018**: 本功能新增后端接口 MUST 使用现有 `/api/v1` 路径及 `{code, message, data, requestId, serverTime}` 响应格式。

### Key Entities

- **Article**：现有文章，新增可选的当前视频关联；继续由现有草稿、发布、下架状态和版本号控制。
- **ArticleVideo**：点播媒资记录，包含点播媒资标识、上传者、归属或待绑定状态、上传及处理状态、可用播放地址和封面等展示信息、创建及更新时间。
- **VideoUploadSession**：一次有权限的上传尝试及其短期授权，用于确认媒资来源、处理失败与未绑定媒资清理。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 管理员可在文章表单中完成“选择视频、上传、保存草稿”的主流程；上传和处理状态在表单中均有明确反馈。
- **SC-002**: 一篇已发布文章在小程序详情中最多出现 1 个视频播放器，且位于正文上方；无视频文章出现空播放器的数量为 0。
- **SC-003**: 处理未就绪的视频随文章发布到小程序的数量为 0；草稿和已下架文章的视频经公开文章接口泄露的数量为 0。
- **SC-004**: 更换已发布文章视频的验收中，从上传到保存前原视频保持可播放；保存后下一次详情请求返回新视频，不出现处理中视频。
- **SC-005**: 在目标 iOS 和 Android 微信环境中，验收视频可播放、暂停、拖动进度和全屏；播放失败时文章正文仍可阅读。
- **SC-006**: 视频上传失败、处理失败和播放失败均有可辨识的提示或重试路径，且不会清空文章已有图文内容。

## Assumptions

- 视频为文章的可选补充内容，允许正文为空；文章标题和分类继续遵循现有校验。
- 视频位于封面、摘要之后及正文之前；若文章无封面或摘要，仅省略对应区块。
- 首期支持 MP4/MOV、单文件不超过 1 GB；这是产品确认的业务限制，不等同于腾讯云点播平台的最大上传限制。
- 视频沿用现有文章的公开访问规则；本期不增加播放地址防盗链或限时访问。
- 点播视频需要可供微信小程序播放的处理结果及合规的 HTTPS 播放域名；具体转码方案、事件接收方式与上传协议在计划阶段确定。
- 现有文章无需迁移出视频数据；视频关联为空时沿用原有展示逻辑。

## Dependencies

- 腾讯云点播应用、上传权限、视频处理配置及 HTTPS 播放域名。
- 现有后台文章管理、文章权限、版本冲突、发布状态与小程序文章详情接口。
- 微信小程序视频播放能力，以及生产环境对点播播放域名的配置。

## Out of Scope

- 一篇文章关联多个视频、在富文本任意位置插入视频、视频直播、用户上传视频。
- 视频弹幕、付费观看、下载、播放进度跨设备同步与播放数据统计面板。
- 改造已有图片 COS 上传和历史图文文章的内容格式。
