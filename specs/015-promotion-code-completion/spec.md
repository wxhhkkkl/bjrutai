**Status**: Draft

**产品规则更新（2026-09-14）**：本推广码明确为“客户绑定码”，供患者扫码后直接归属发码业务员；不再要求业务员在生成二维码前填写患者手机号。业务员加入组织使用规格 019 定义的独立“业务员加入码”。

**首页视觉调整（2026-09-18）**：保留现有首页轮播图和文章接口，以及底部 Tab；首页主体调整为品牌欢迎区、轮播图与“关于儒泰 / 心脑维养 / 健康资讯”三个内容入口。入口必须继续跳转到对应已发布文章或文章分类，不得以静态内容替代接口数据。

**首页视觉调整（2026-09-23，取代上述布局）**：按用户最新确认，首页恢复至 2026-09-18 改版前的欢迎文案、独立轮播图、心脑维养、健康资讯、关于儒泰分区布局；“关于儒泰”紧接在轮播图下方。保留现有文章与轮播接口、分类各最多 3 条文章、跳转行为及底部 Tab。此次调整仅限小程序首页展示和相应测试，不修改其他页面、管理后台或后端服务。

**首页女性专区（2026-09-23）**：在“心脑维养”下方、“健康资讯”上方展示“女性专区”，读取已发布的“女性专区”分类文章，最多显示 3 篇。采用横向图文主卡与编号文章列表，区别于现有分区；保留文章详情和分类列表入口，并独立处理加载、空内容、请求失败状态。“健康资讯”优先展示其他分类，再补充女性专区中未在上方展示的文章，避免重复。

**关于儒泰封面调整（2026-09-23）**：关于儒泰主卡只展示文章封面原图，移除封面上的文章文案和遮罩；主卡仍可点击进入文章详情。

**健康资讯排版调整（2026-09-23）**：健康资讯文章列表增加左右内边距，并扩大文章行的上下间距、标题与摘要之间的间距，提升内容可读性。

**首页文字层级调整（2026-09-23）**：放大首页分类标签、辅助说明、摘要和状态提示等小字号文案，保留主标题层级和各模块的视觉区分。

## User Scenarios & Testing

**首页微信分享（2026-11-03）**：首页开放“转发给朋友”和“分享到朋友圈”，不要求登录、不依赖文章和轮播接口成功。分享标题为“儒泰医联｜让健康知识，走进日常”；好友分享落地 `/pages/home/index`，朋友圈不附带账号或客户参数。分别提供 5:4 好友封面和 1:1 朋友圈图片，封面介绍“心脑维养 · 女性健康 · 健康资讯”，不包含疗效承诺、客户数据或推广归属令牌。访客打开分享后继续使用既有公开首页。

**首页分类入口调整（2026-11-03）**：按用户提供参考图，在轮播图下方增加两侧分割线及“敬请点击以下图标，进入详情页面了解”提示，下方横排“关于儒泰 / 心脑维养 / 女性专区 / 健康资讯”四个圆角方形图标入口。前三项复用现有分类跳转，健康资讯复用现有“查看全部”跳转；访客也可使用。入口始终可见，不依赖轮播加载成功。保留用户已调整的轮播高度及下方所有内容布局。

**首页入口视觉优化（2026-11-03）**：按用户二次反馈，加粗提示分割线、放大提示文案；四个入口改用统一立体插画图片，分别表现健康机构楼宇、心脑维养、女性健康和健康读物。轮播底部渐隐至深青色，入口区与关于儒泰共用深青色背景，移除两者之间浅色间隔，改善衔接；保留轮播高度、分类跳转和后续内容。

**我的服务消费入口调整（2026-11-03）**：移除底部“消费”Tab，将消费入口放到“我的服务”中原“消费明细”卡片的位置并改名为“消费记录”。该入口打开原消费汇总页作为可返回的二级页面；“查看全部”继续进入逐笔记录页。消费能力仍限于具备相应业务权限的账号。

### User Story 1 - 查看并保存有效推广码 (Priority: P1)

已通过资质的拓展人打开“我的推广码”，看到后端配置的二维码；可将其保存至相册。

**Acceptance Scenarios**:

1. **Given** 后端已有有效二维码，**When** 用户打开页面，**Then** 页面展示二维码且保存按钮可用。
2. **Given** 用户授权相册权限，**When** 点击保存，**Then** 图片下载并保存成功。
3. **Given** 二维码尚未由儒泰侧生成，**When** 用户打开页面，**Then** 页面清楚说明暂不可保存，不展示伪造二维码。

### User Story 2 - 分享和归属令牌一致 (Priority: P1)

拓展人分享推广码时，分享标题、路径和二维码均使用同一推广记录的令牌；同步客户仅在令牌有效匹配时归属推广员。

**Acceptance Scenarios**:

1. **Given** 后端返回 `sharePath`，**When** 用户分享，**Then** 分享使用该路径而非本地硬编码路径。
2. **Given** 儒泰回传未知或缺失 `ref_token`，**When** 同步客户，**Then** 系统不将客户错误归属给任意推广员。

### User Story 3 - 补齐已存在接口的小程序入口 (Priority: P2)

用户可以保存首次资料、查看客户服务与消费记录、记录跟进，并查看或重试失败的绑定请求。

**Acceptance Scenarios**:

1. **Given** 新用户完成资料填写，**When** 提交，**Then** 姓名和机构保存到用户资料服务。
2. **Given** 用户打开客户详情的服务或消费标签，**When** 服务端有数据，**Then** 页面展示服务端返回的记录。
3. **Given** 用户填写合法跟进内容，**When** 保存，**Then** 服务端创建跟进记录和可选提醒。
4. **Given** 绑定请求失败或过期，**When** 用户查看详情并确认重试，**Then** 小程序调用已有重试接口。

## Requirements

- **FR-001**: 小程序必须使用 API 的 `qrImageUrl`、`posterUrl` 和 `sharePath` 字段；分享标题与封面按 FR-024 的用户确认设计呈现。
- **FR-002**: 推广码页首次加载必须先确保推广码存在，再请求海报，避免并发竞态。
- **FR-003**: 保存图片必须调用微信下载和相册保存 API，并处理拒绝授权与失败状态。
- **FR-004**: 后端响应必须返回推广码记录标识、状态说明、令牌关联的分享路径及二维码状态。
- **FR-005**: 客户同步必须拒绝没有有效 `ref_token` 的自动归属；不得回退到首位推广员。
- **FR-006**: 本仓库不伪造哈尔滨儒泰小程序码生成 API；其二维码 URL 由已确认的外部服务或后台配置提供。
- **FR-007**: 已存在的客户服务、消费、跟进、绑定详情/重试和资料更新 API 必须由对应小程序页面调用，不得继续以建设中提示替代。
- **FR-008**: 首页必须保留后台轮播图读取、点击跳转与图片失败降级；轮播加载失败不得阻塞其余首页入口。
- **FR-009**: 首页必须展示“心脑维养”“健康资讯”“关于儒泰”内容分区，保留对应文章与分类跳转，并继续由现有文章接口提供内容；“心脑维养”和“关于儒泰”各最多展示 3 条文章。
- **FR-010**: 首页“女性专区”必须从公开文章接口按“女性专区”分类读取最多 3 篇已发布文章；文章和分类入口均可跳转，且其加载、空内容、失败状态不得影响其他分区。
- **FR-011**: 关于儒泰主卡必须展示无文案、无遮罩的文章封面，并保留文章详情跳转。
- **FR-012**: 健康资讯列表必须保留文章内容左右内边距，并为文章行和文字层级提供清晰的垂直间距。
- **FR-013**: 首页辅助文案的字号必须满足小程序手机屏幕上的可读性，分类、摘要、状态提示等小字号内容统一提升一级，主标题层级保持不变。
- **FR-014**: 客户扫码绑定收到身份冲突错误 `40024` 时，完整显示“该手机号已是客户顾问账号，不能作为客户绑定”，提示可自动换行且不截断；提示停留 3 秒后返回首页，等待期间禁用重复提交。其他错误保留重试；页面卸载时取消跳转计时。
- **FR-016**: 小程序预览包大小 MUST 小于微信开发者工具 2 MB 限制；首页静态图片应使用适合展示尺寸的压缩格式，原始图只保留在项目目录时必须通过 `packOptions.ignore` 排除出预览包。
- **FR-015（2026-11-05 用户确认修订）**: 首页顶部品牌栏保持不变；有轮播图时，轮播区域填充品牌栏下方至底部 Tab 栏上方的首屏空间。轮播底部显示“更多精彩请上划”提示，四个分类图标入口区移除；下方已有内容仍可通过上划浏览。

- **FR-017**: 首页必须实现原生好友与朋友圈分享回调，主动显示两个分享菜单；标题和两种本地封面稳定可用，分享不携带会话或身份信息，不依赖内容请求状态，不新增不受微信支持的独立描述字段或 page.json 分享开关。
- **FR-022**: 底部导航不显示“消费”Tab；具备消费权限的业务账号可从“我的服务”的“消费记录”入口打开原消费汇总页，该页作为二级页面提供返回操作，并保留进入逐笔消费记录页的入口。无消费权限的账号不得看到或打开此入口。
- **FR-023**: 在“客户”后、“我的”前新增公开的“互联网医院”Tab，使用建筑样式图标，打开左上角带“互联网医院”标题的原生占位页，展示用户选定的第二版青绿插画和“互联网医院正在建设中 / 我们正在用心完善服务体验 / 敬请期待”说明。图片等比完整显示，适配微信胶囊及底部安全区；加载失败时保留同义文字说明，不提供尚未上线的诊疗操作，不依赖登录或接口。

- **FR-024（2026-11-03，用户确认）**: 客户绑定码分享好友时，使用独立的 5:4 青绿品牌邀请封面，包含“儒泰医联 / 您的专属健康服务入口 / 点击进入，关联专属客户顾问”，不把二维码作为封面；分享标题为“儒泰医联｜您的专属健康服务入口”。优先保留 API 的 `sharePath`，缺失时继续使用当前记录 `refToken` 构建原绑定路由。封面不包含个人数据或令牌；页面二维码展示与保存图片继续使用原二维码。已有朋友圈回调同步标题，封面添加上下留白适配 1:1，避免裁切文字。

**FR-024 验收**：二维码不可用时品牌封面仍可用；后端自定义路径原样保留；回退路径正确编码当前令牌；保存原二维码不受影响；检查封面完整尺寸及聊天缩略图中文字可读性。微信真实聊天最终展示待真机复核。

**FR-024 封面调整（2026-11-04）**：按用户标注删除图片中“点击进入，关联专属客户顾问”一行，延用其余画面与两种分享封面尺寸，替换现有分享图片资源。

- **FR-025（2026-11-04，用户确认）**: 客户绑定码验证通过后展示选定的青绿欢迎插画、提示“点击下方按钮，按微信提示授权手机号。”及单个黑色“确认登陆小程序”按钮。移除勾选项与页面勾选校验，按钮直接打开微信手机号授权。仅取得有效授权凭证后提交原客户绑定请求。保留验证中、无效码、失败、成功与独立的延迟登录补绑确认。

## Success Criteria

- **SC-001**: 已配置二维码的用户可在一次页面加载后展示、分享、保存同一推广记录。
- **SC-002**: 首次生成推广令牌不会因海报请求竞态而使页面失败。
- **SC-003**: 缺失或未知令牌的同步记录不会创建错误归属客户。

## 延迟登录补绑（2026-11-03 / FR-018）

用户打开客户绑定码但未提交绑定，转去首页浏览，稍后登录时可继续确认并补齐归属。

- **FR-018**: 扫码页保存最近一次验证有效的 `refToken` 和保存时间，不保存手机号或登录凭证；有效期 7 天，跨页面/重启保留，切换 API 环境时清除。新有效码替换旧码；无效码不得成为新来源。
- **FR-019**: 普通用户登录成功或已登录后返回首页时，读取待绑定来源并重新校验码；展示顾问姓名及“授权使用登录手机号建立客户归属”的确认弹窗。同意后以当前登录用户发起补绑，不复用微信一次性手机号 code。取消则清除该待绑定来源，不影响登录及原跳转。业务成员不执行补绑。
- **FR-020**: 新增需登录的 `POST /api/v1/customer-binding-codes/{refToken}/claim-session`，body 仅需 `consentConfirmed: true`；身份和手机号仅取服务端当前活跃个人账号，不接受客户端指定客户或手机号。保留客户顾问身份限制、码有效性/组织人员状态、已有归属冲突、同顾问重复请求幂等和待儒泰匹配语义；记录绑定授权证据。响应沿用 claim 的绑定结果字段但不返回新会话。
- **FR-021**: 成功、明确取消、失效码、已有归属冲突或业务账号限制时清除对应来源；网络/服务失败保留来源，提示稍后返回首页重试，60 秒内不重复提示，防止登录和首页连续触发。并发只允许一个确认/请求；迟到的旧请求不得清除后来扫码的新来源。原扫码直接授权绑定链路继续可用，成功后同样清除来源。

**验收场景**：
1. 未登录扫码 A → 返回首页 → 重启后普通登录 → 确认顾问 A → 未分配客户成为 A 的客户；登录原本的首页/我的/评论返回目标保留。
2. 拒绝确认或无待绑定来源 → 不调用补绑接口，正常完成登录；拒绝后不再次提示。
3. 已登录扫码后返回首页也可继续补绑；重复触发只出现一次确认，请求重试不重复客户、绑定请求和统计。
4. 码失效/过期、顾问或组织停用、已有其他顾问、业务账号，均不建立或覆盖归属；终态清除来源。
5. 断网/服务错误保留来源，稍后可重试；未登录/授权不确认的补绑接口请求被拒绝。
6. 来源本地过期/API 切换时不继续使用；新有效扫码替换旧码，迟到的请求不影响新来源。

**设计变更记录**：复用微信原生确认弹窗，无新增页面布局；登录授权与客户归属授权分别确认，保留现有扫码页视觉和错误停留行为。
