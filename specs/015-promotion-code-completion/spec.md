**Feature Branch**: `015-promotion-code-completion`  
**Created**: 2026-08-10  
**Status**: Draft  
**Input**: 完善“我的推广码”链路中可在北京儒泰仓库内实现的缺失部分。

**临时产品调整（2026-09-02）**：首页和“我的”页暂时隐藏“我的推广码”入口；页面、路由与后端能力保留，待产品确认后恢复入口。

**产品规则更新（2026-09-14）**：本推广码明确为“客户绑定码”，供患者扫码后直接归属发码业务员；不再要求业务员在生成二维码前填写患者手机号。业务员加入组织使用规格 019 定义的独立“业务员加入码”。

**首页视觉调整（2026-09-18）**：保留现有首页轮播图和文章接口，以及底部 Tab；首页主体调整为品牌欢迎区、轮播图与“关于儒泰 / 心脑维养 / 健康资讯”三个内容入口。入口必须继续跳转到对应已发布文章或文章分类，不得以静态内容替代接口数据。

**首页视觉调整（2026-09-23，取代上述布局）**：按用户最新确认，首页恢复至 2026-09-18 改版前的欢迎文案、独立轮播图、心脑维养、健康资讯、关于儒泰分区布局；“关于儒泰”紧接在轮播图下方。保留现有文章与轮播接口、分类各最多 3 条文章、跳转行为及底部 Tab。此次调整仅限小程序首页展示和相应测试，不修改其他页面、管理后台或后端服务。

**首页女性专区（2026-09-23）**：在“心脑维养”下方、“健康资讯”上方展示“女性专区”，读取已发布的“女性专区”分类文章，最多显示 3 篇。采用横向图文主卡与编号文章列表，区别于现有分区；保留文章详情和分类列表入口，并独立处理加载、空内容、请求失败状态。“健康资讯”优先展示其他分类，再补充女性专区中未在上方展示的文章，避免重复。

**关于儒泰封面调整（2026-09-23）**：关于儒泰主卡只展示文章封面原图，移除封面上的文章文案和遮罩；主卡仍可点击进入文章详情。

**健康资讯排版调整（2026-09-23）**：健康资讯文章列表增加左右内边距，并扩大文章行的上下间距、标题与摘要之间的间距，提升内容可读性。

**首页文字层级调整（2026-09-23）**：放大首页分类标签、辅助说明、摘要和状态提示等小字号文案，保留主标题层级和各模块的视觉区分。

## User Scenarios & Testing

### User Story 1 - 查看并保存有效推广码 (Priority: P1)

已通过资质的拓展人打开“我的推广码”，看到后端配置的二维码；可将其保存至相册。

**Acceptance Scenarios**:

1. **Given** 后端已有有效二维码，**When** 用户打开页面，**Then** 页面展示二维码且保存按钮可用。
2. **Given** 用户授权相册权限，**When** 点击保存，**Then** 图片下载并保存成功。
3. **Given** 二维码尚未由儒泰侧生成，**When** 用户打开页面，**Then** 页面清楚说明暂不可保存，不展示伪造二维码。

### User Story 2 - 分享和归属令牌一致 (Priority: P1)

拓展人分享推广码时，分享标题、路径和二维码均使用同一推广记录的令牌；同步客户仅在令牌有效匹配时归属推广员。

**Acceptance Scenarios**:

1. **Given** 后端返回 `sharePath`，**When** 用户分享，**Then** 分享使用该路径而非本地硬编码路径。
2. **Given** 儒泰回传未知或缺失 `ref_token`，**When** 同步客户，**Then** 系统不将客户错误归属给任意推广员。

### User Story 3 - 补齐已存在接口的小程序入口 (Priority: P2)

用户可以保存首次资料、查看客户服务与消费记录、记录跟进，并查看或重试失败的绑定请求。

**Acceptance Scenarios**:

1. **Given** 新用户完成资料填写，**When** 提交，**Then** 姓名和机构保存到用户资料服务。
2. **Given** 用户打开客户详情的服务或消费标签，**When** 服务端有数据，**Then** 页面展示服务端返回的记录。
3. **Given** 用户填写合法跟进内容，**When** 保存，**Then** 服务端创建跟进记录和可选提醒。
4. **Given** 绑定请求失败或过期，**When** 用户查看详情并确认重试，**Then** 小程序调用已有重试接口。

## Requirements

- **FR-001**: 小程序必须使用 API 的 `qrImageUrl`、`posterUrl`、`shareTitle` 和 `sharePath` 字段。
- **FR-002**: 推广码页首次加载必须先确保推广码存在，再请求海报，避免并发竞态。
- **FR-003**: 保存图片必须调用微信下载和相册保存 API，并处理拒绝授权与失败状态。
- **FR-004**: 后端响应必须返回推广码记录标识、状态说明、令牌关联的分享路径及二维码状态。
- **FR-005**: 客户同步必须拒绝没有有效 `ref_token` 的自动归属；不得回退到首位推广员。
- **FR-006**: 本仓库不伪造哈尔滨儒泰小程序码生成 API；其二维码 URL 由已确认的外部服务或后台配置提供。
- **FR-007**: 已存在的客户服务、消费、跟进、绑定详情/重试和资料更新 API 必须由对应小程序页面调用，不得继续以建设中提示替代。
- **FR-008**: 首页必须保留后台轮播图读取、点击跳转与图片失败降级；轮播加载失败不得阻塞其余首页入口。
- **FR-009**: 首页必须展示“心脑维养”“健康资讯”“关于儒泰”内容分区，保留对应文章与分类跳转，并继续由现有文章接口提供内容；“心脑维养”和“关于儒泰”各最多展示 3 条文章。
- **FR-010**: 首页“女性专区”必须从公开文章接口按“女性专区”分类读取最多 3 篇已发布文章；文章和分类入口均可跳转，且其加载、空内容、失败状态不得影响其他分区。
- **FR-011**: 关于儒泰主卡必须展示无文案、无遮罩的文章封面，并保留文章详情跳转。
- **FR-012**: 健康资讯列表必须保留文章内容左右内边距，并为文章行和文字层级提供清晰的垂直间距。
- **FR-013**: 首页辅助文案的字号必须满足小程序手机屏幕上的可读性，分类、摘要、状态提示等小字号内容统一提升一级，主标题层级保持不变。

## Success Criteria

- **SC-001**: 已配置二维码的用户可在一次页面加载后展示、分享、保存同一推广记录。
- **SC-002**: 首次生成推广令牌不会因海报请求竞态而使页面失败。
- **SC-003**: 缺失或未知令牌的同步记录不会创建错误归属客户。
