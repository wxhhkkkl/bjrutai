# Feature Specification: 我的推广码闭环完善

**Feature Branch**: `015-promotion-code-completion`  
**Created**: 2026-08-10  
**Status**: Draft  
**Input**: 完善“我的推广码”链路中可在北京鲁泰仓库内实现的缺失部分。

## User Scenarios & Testing

### User Story 1 - 查看并保存有效推广码 (Priority: P1)

已通过资质的拓展人打开“我的推广码”，看到后端配置的二维码；可将其保存至相册。

**Acceptance Scenarios**:

1. **Given** 后端已有有效二维码，**When** 用户打开页面，**Then** 页面展示二维码且保存按钮可用。
2. **Given** 用户授权相册权限，**When** 点击保存，**Then** 图片下载并保存成功。
3. **Given** 二维码尚未由儒泰侧生成，**When** 用户打开页面，**Then** 页面清楚说明暂不可保存，不展示伪造二维码。

### User Story 2 - 分享和归属令牌一致 (Priority: P1)

拓展人分享推广码时，分享标题、路径和二维码均使用同一推广记录的令牌；同步客户仅在令牌有效匹配时归属推广员。

**Acceptance Scenarios**:

1. **Given** 后端返回 `sharePath`，**When** 用户分享，**Then** 分享使用该路径而非本地硬编码路径。
2. **Given** 儒泰回传未知或缺失 `ref_token`，**When** 同步客户，**Then** 系统不将客户错误归属给任意推广员。

### User Story 3 - 补齐已存在接口的小程序入口 (Priority: P2)

用户可以保存首次资料、查看客户服务与消费记录、记录跟进，并查看或重试失败的绑定请求。

**Acceptance Scenarios**:

1. **Given** 新用户完成资料填写，**When** 提交，**Then** 姓名和机构保存到用户资料服务。
2. **Given** 用户打开客户详情的服务或消费标签，**When** 服务端有数据，**Then** 页面展示服务端返回的记录。
3. **Given** 用户填写合法跟进内容，**When** 保存，**Then** 服务端创建跟进记录和可选提醒。
4. **Given** 绑定请求失败或过期，**When** 用户查看详情并确认重试，**Then** 小程序调用已有重试接口。

## Requirements

- **FR-001**: 小程序必须使用 API 的 `qrImageUrl`、`posterUrl`、`shareTitle` 和 `sharePath` 字段。
- **FR-002**: 推广码页首次加载必须先确保推广码存在，再请求海报，避免并发竞态。
- **FR-003**: 保存图片必须调用微信下载和相册保存 API，并处理拒绝授权与失败状态。
- **FR-004**: 后端响应必须返回推广码记录标识、状态说明、令牌关联的分享路径及二维码状态。
- **FR-005**: 客户同步必须拒绝没有有效 `ref_token` 的自动归属；不得回退到首位推广员。
- **FR-006**: 本仓库不伪造哈尔滨儒泰小程序码生成 API；其二维码 URL 由已确认的外部服务或后台配置提供。
- **FR-007**: 已存在的客户服务、消费、跟进、绑定详情/重试和资料更新 API 必须由对应小程序页面调用，不得继续以建设中提示替代。

## Success Criteria

- **SC-001**: 已配置二维码的用户可在一次页面加载后展示、分享、保存同一推广记录。
- **SC-002**: 首次生成推广令牌不会因海报请求竞态而使页面失败。
- **SC-003**: 缺失或未知令牌的同步记录不会创建错误归属客户。
