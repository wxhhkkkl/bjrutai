# 端到端验收走查（T070）

对照 spec.md 成功标准 SC-001 ~ SC-011 的逐项走查清单。执行顺序建议从「准备」到「小程序闭环」。

## 准备

1. **后端**：`cd backend && ./venv/Scripts/python.exe -m uvicorn src.main:app --host 0.0.0.0 --port 8000`（已由本会话启动时可用 `curl http://127.0.0.1:8000/api/v1/health` 验证）。
2. **管理后台**：`cd manageSystem && npm run dev`，浏览器打开 Vite 提示的地址。
3. **小程序**：微信开发者工具导入 `miniProgram/` 目录：
   - 「详情 → 本地设置」勾选 **不校验合法域名**（本机调试走 `http://127.0.0.1:8000`）。
   - 「工具 → 构建 npm」生成 `miniprogram_npm`（同时解决 vant 图标契约测试）。
   - `app.js` 中 `globalData.apiBase` 为本机后端地址；真机调试需改为局域网 IP。
4. **测试数据**：后台需存在组织树 + 分销员 + 组织资质 + 组织管理员，由走查第 1 步创建。
5. **管理员凭据**：`admin` / `change-me-immediately`（本次已用该凭据创建测试数据）。
6. **测试数据（已种入）**：组织树 `北京儒泰总部 → 华北区 → 石家庄`；总部组织资质已审核通过；分销员 `13800000001` / `pass12345`（总部组织管理员）。分销员首次登录会进入微信绑定步骤。

## 后台：组织人员管理

### SC-001 / SC-002 / SC-004 — 组织树闭环（5 分钟内）
1. 侧栏「组织人员管理」→ 新建根组织（如「北京儒泰总部」）。
2. 在其下新建多级子组织（如「华北区」→「石家庄」），确认树形即时展示。
3. 编辑某组织名称/排序，确认生效。
4. 整体迁移：把「石家庄」迁到另一分支，确认子树随迁、历史记录（操作历史页签）出现。
5. **环路拦截**：把上级组织迁到其自己的下级下，应被拒绝并提示「组织关系不允许形成闭环」。
6. **删除非空组织**：删除仍含下级或分销员的组织，应被拒绝并给出处理引导。

### SC-005 — 组织资质
1. 打开某组织详情 → 「资质文件」页签 → 上传资质（营业执照等），状态为「审核中」。
2. 用有审核权限的账号审核通过 → 组织业务可用。
3. 设置 30 天内到期资质，观察到期提醒；过期后确认该组织下分销员暂停新推广码/贡献累计（保留登录与历史）。

### SC-011 — 权限拦截
1. 用无 `org.read`/`org.write` 权限的角色账号访问组织管理接口，应被拦截并提示无权限。
2. 用无 `org_admin:assign` 权限的账号设置组织管理员，应被拒绝。

## 后台：分销员与管理

### SC-001 / SC-004 — 分销员闭环
1. 组织详情 → 「分销员」→ 新建账户（姓名 + 11 位手机号 + 初始密码），确认归属该组织。
2. 用同一手机号在其他组织新建，应提示「该手机号已存在分销员账户」。
3. 调整归属 / 停用 / 重置凭证，确认生效。

### SC-008 / FR-013 — 组织管理员
1. 「组织管理员」页签：将某分销员设为管理员（`org_admin:assign`），确认即时生效。
2. 撤销管理员，确认小程序端入口即时消失。

---

## 小程序：登录 → 组织业绩闭环

### FR-027 / SC-003 / SC-006 / SC-007 — 分销员登录
1. 打开小程序 → 使用 **手机号 + 密码** 登录（T052）。
2. 首次登录：若 `requiresWechatBinding=true`，进入「绑定微信」页完成绑定（需真实微信 AppID；DevTools 用测试号亦可，绑定后返回 home）。
3. 非组织管理员登录后：无「组织业绩」入口。

### SC-003 / SC-006 / SC-007 — 组织业绩查看
1. 组织管理员登录 → 「我的 → 组织业绩」入口可见。
2. 进入查看：组织汇总（本月/累计）+ 下级组织 + 成员贡献值；切换月份数据变化。
3. 核对一致性：组织汇总 = 各成员贡献值之和（SC-006，偏差为 0）。
4. 越权：组织管理员无法看到授权组织子树之外的数据；撤销授权后入口消失（SC-008）。

## 数据一致性（SC-009 / SC-010）

迁移完整性由 `backend/scripts/verify_migration.py` 校验（行数 / 贡献值求和 / 客户绑定数 / 推广码数，与迁移前一致）。执行：

```bash
cd backend
./venv/Scripts/python.exe scripts/verify_migration.py
```

迁移后现有功能（个人贡献看板、推广码、客户绑定、分账规则、对账报表）在组织/分销员模型下正常：

- 推广码：组织资质通过后生成专属二维码，刷新/统计可用。
- 对账报表：`数据报表` 生成含「绑定/分配」维度报表，明细按**组织维度**聚合（US6-AC6）。
- 分账规则：`分成规则` 新增规则时组织层级下拉来自组织树（任意深度，FR-005）。
