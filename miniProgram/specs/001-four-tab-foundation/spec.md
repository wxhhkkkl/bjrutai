# Feature Specification: 四 Tab 基础工程与角色工作台

**Feature Branch**: `001-four-tab-foundation`

**Created**: 2026-07-27

**Status**: Ready for Implementation

**Input**: 将 LuTaiPage 建立为北京鲁泰微信小程序的正式开发工程，
先完成角色入口、四个底部 Tab、公共视觉规则和可独立验收的页面外壳。

## Scope & References

### In Scope

- 登录后根据角色进入拓展人首页、医生工作台或资质审核状态。
- 提供首页、客户、贡献、我的四个底部 Tab。
- 按已确认设计稿展示四个一级页面的结构、导航和模拟摘要数据。
- 建立公共视觉规则、页面状态和路由目标的统一约束。
- 提供登录、首次资料补全、资质状态和功能建设中的可演示占位页面。
- 使用非真实模拟数据完成独立验收。

### Out of Scope

- 真实登录、手机号授权和后端会话交换。
- 客户绑定、客户详情、贡献明细、资质更新等二级业务的完整实现。
- 儒泰接口联调、账单同步、贡献计算和后台管理。
- 在线问诊、诊断、处方、支付或医疗消费画像。

## User Scenarios & Testing

### User Story 1 - 按角色进入正确工作台 (Priority: P1)

已完成登录识别的用户打开小程序后，应直接看到与其角色和资质状态匹配的工作台，
而不需要在多个入口之间猜测。

**Why this priority**: 错误的角色入口会暴露无权功能，并阻断后续所有业务流程。

**Independent Test**: 分别设置拓展人、医生和待审核拓展人模拟身份后重新进入小程序，
可独立验证三个身份均落到正确首页状态。

**Acceptance Scenarios**:

1. **Given** 用户为已激活拓展人，**When** 用户进入小程序，
   **Then** 展示拓展人首页及其推广、贡献和资质入口。
2. **Given** 用户为医生，**When** 用户进入小程序，
   **Then** 展示医生工作台及客户绑定入口。
3. **Given** 用户为待审核或审核驳回的拓展人，**When** 用户进入小程序，
   **Then** 优先展示对应资质状态，不开放受限制的推广能力。
4. **Given** 用户账号未激活，**When** 用户进入小程序，
   **Then** 展示“账号待激活”状态，不开放推广二维码和贡献能力。
5. **Given** 用户身份已识别但资料未补全，**When** 用户进入小程序，
   **Then** 进入首次资料补全页。
6. **Given** 用户无有效会话或角色尚未识别，**When** 用户进入小程序，
   **Then** 进入登录授权页。
7. **Given** 拓展人资质即将过期，**When** 用户进入小程序，
   **Then** 进入拓展人首页，并可见资质续期提醒和资质状态入口。

---

### User Story 2 - 在四个一级页面间稳定切换 (Priority: P1)

用户可以通过底部 Tab 在首页、客户、贡献、我的之间切换，并始终理解当前位置。

**Why this priority**: 四个 Tab 是全部已确认页面和后续功能的主导航骨架。

**Independent Test**: 从任意一级页面依次点击四个 Tab，验证目标页面、选中状态、
页面保留规则和安全区表现。

**Acceptance Scenarios**:

1. **Given** 用户位于任意一级页面，**When** 点击另一 Tab，
   **Then** 一次点击进入目标页面并突出正确选中态。
2. **Given** 用户位于客户、贡献或我的 Tab，**When** 页面展示，
   **Then** 页面不出现返回按钮或页面标题导航。
3. **Given** 用户位于首页，**When** 页面展示，
   **Then** 保留已确认的品牌区、扫码、通知和微信胶囊安全位置。
4. **Given** 用户从一级页面进入二级页面后返回，
   **When** 返回原 Tab，**Then** 原 Tab 仍保持正确选中状态。

---

### User Story 3 - 查看一致且安全的一级页面摘要 (Priority: P2)

用户在四个一级页面中看到符合设计稿的信息层级、公共组件和脱敏模拟数据，
从而可以在后端接口完成前评审整体体验。

**Why this priority**: 统一的视觉和状态基础能降低后续 20 多个业务页面的重复开发成本。

**Independent Test**: 使用模拟数据打开四个一级页面，核对视觉规则、触控区域、
文本溢出、脱敏信息和空/错状态。

**Acceptance Scenarios**:

1. **Given** 一级页面有模拟数据，**When** 页面渲染，
   **Then** 数据、图标、按钮和状态标签符合已确认设计规则。
2. **Given** 一级页面没有数据，**When** 页面渲染，
   **Then** 展示可理解的空状态，不显示错误占位文本。
3. **Given** 数据加载失败，**When** 页面渲染，
   **Then** 展示可恢复错误和重试动作，不阻断 Tab 切换。
4. **Given** 页面显示客户相关示例，**When** 用户查看，
   **Then** 不出现真实个人信息，敏感字段保持脱敏。

### Edge Cases

- 本地角色缓存缺失、损坏或包含未知角色值。
- 用户资质状态在应用运行期间发生变化。
- 连续快速点击多个 Tab。
- 一级页面首次加载、重复进入或从二级页返回。
- 数据为空、请求超时或无权限。
- 小屏设备、长文字、系统字体放大和底部安全区变化。

### Privacy and State Requirements

- 模拟数据不得来自真实客户、真实身份证、医保账户或资质文件。
- 手机号和客户标识必须使用明显的脱敏示例。
- 每个一级页面必须具有加载、空数据、成功、可恢复错误和无权限状态。
- 儒泰小程序和后端数据同步属于外部依赖，本功能只定义入口和占位状态。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供首页、客户、贡献、我的四个固定一级入口。
- **FR-002**: 系统 MUST 在任何一级页面清晰标识当前选中的 Tab。
- **FR-003**: 系统 MUST 根据拓展人、医生、待审核、驳回、未激活、资料未补全和无有效会话选择正确入口状态。
- **FR-004**: 系统 MUST 在客户、贡献和我的 Tab 隐藏页面级返回/标题导航。
- **FR-005**: 系统 MUST 在首页保留品牌区和微信原生胶囊安全空间。
- **FR-006**: 系统 MUST 使用统一的颜色、字号、间距、按钮、状态标签和图标容器规则。
- **FR-007**: 系统 MUST 为一级页面提供加载、空数据、成功、可恢复错误和无权限状态，并可通过非生产 Mock 控制在不修改源码的情况下切换。
- **FR-008**: 系统 MUST 使用可替换的模拟摘要数据支持独立演示和验收。
- **FR-009**: 系统 MUST 保证示例客户信息脱敏且不包含真实个人数据。
- **FR-010**: 系统 MUST 允许二级页面返回后恢复原一级页面的选中状态。
- **FR-011**: 所有主要交互区域 MUST 不小于 44 点，并适配顶部和底部安全区。
- **FR-012**: 系统 MUST 对未知角色或无有效会话提供明确的登录/补全资料入口。
- **FR-013**: 一级页面 MUST 为已确认主操作提供已注册的路由目标；尚未实现的业务页必须进入可返回的“功能建设中”占位页，不得使用无响应装饰按钮。
- **FR-014**: Tab 页面 MUST 使用真实组件渲染，禁止将设计稿截图作为交互背景。

### Key Entities

- **UserSession**: 当前用户身份、角色、激活状态、资质状态和会话可用性。
- **NavigationTab**: 一级入口标识、标题、图标、选中图标和目标页面。
- **WorkbenchSummary**: 首页、客户、贡献和我的页面所需的摘要指标与状态。
- **PageViewState**: 加载、成功、空数据、可恢复错误和无权限状态。
- **NavigationTarget**: 一级页面中已确认操作对应的二级页面标识。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 测试用户从任意一级页面进入另一一级页面只需一次点击。
- **SC-002**: 四个一级页面及已定义的账户、角色和资质入口验收场景通过率达到 100%。
- **SC-003**: 在选定的 iOS 和 Android 微信视口中，一级页面无文字遮挡、
  内容横向溢出或底部 Tab 被安全区遮挡。
- **SC-004**: 所有主要点击区域均达到 44 点最低尺寸。
- **SC-005**: 模拟数据、界面和日志中真实个人信息出现次数为 0。
- **SC-006**: 加载、空数据、错误和无权限状态均可在不修改代码的情况下触发演示。
- **SC-007**: 产品或设计评审可从四个一级页面到达 100% 已定义的主操作目标。
- **SC-008**: 在微信开发者工具的本地模拟数据环境中，四个一级页面首次可交互时间均不超过 2 秒，并记录测量结果。

## Assumptions

- 本阶段使用模拟角色和模拟摘要数据，真实接口在后续独立规格中接入。
- 工程采用原生微信小程序和 JavaScript；不使用 TypeScript 或跨端框架。
- Vant Weapp 是可选的预批准 UI 库，本功能不依赖它完成验收。
- 首页根据用户角色切换内容，底部 Tab 数量保持四个。
- 待审核和审核驳回用户的受限能力遵循现有 PRD。
- `activationStatus=inactive` 使用资质状态页的“账号待激活”内容状态，沿用已确认的待审核状态页面结构；该状态不开放推广二维码和贡献能力。
- `qualificationStatus=expiring` 保持拓展人首页入口，但必须展示续期提醒和资质状态入口。
- 当前确认稿是视觉基线；画布尺寸差异在实现时按同一设备安全区归一化。
- 二级业务页面可以先提供路由目标，具体内容由后续功能规格实现。
