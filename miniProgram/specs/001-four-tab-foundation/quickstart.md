# Quickstart Validation: 四 Tab 基础工程与角色工作台

## Prerequisites

1. 安装微信开发者工具。
2. 使用开发者工具导入 `LuTaiPage/`。
3. 在开发者工具中选择并固定团队支持的稳定基础库。
4. 确保使用本地模拟数据，不连接生产接口。

## Scenario 1: Role Entry

1. 将模拟角色设置为 `promoter`、账户状态为 `active` 且资质为 `approved`。
2. 重新编译，预期进入拓展人首页。
3. 将角色改为 `doctor`，重新编译，预期进入医生工作台。
4. 将拓展人资质改为 `reviewing`，重新编译，预期进入资质状态。
5. 将账户状态改为 `inactive`，预期进入“账号待激活”资质状态，且无推广或贡献入口。
6. 将已识别身份的 `profileCompleted` 改为 `false`，预期进入首次资料补全页。
7. 清空模拟会话或将角色改为 `unknown`，预期进入登录授权页。
8. 将拓展人资质改为 `expiring`，预期进入拓展人首页并显示续期提醒入口。

## Scenario 2: Four Tabs

1. 依次点击首页、客户、贡献、我的。
2. 每次只点击一次即可进入目标页面。
3. 客户、贡献、我的不显示返回按钮或页面标题导航。
4. 当前 Tab 选中态始终与页面一致。
5. 从二级占位页面返回后，原 Tab 仍保持选中。

## Scenario 3: Shared States

使用 `mock/demo-control.js` 定义的开发环境本地存储键，对每个一级页面依次切换模拟状态：

- `loading`
- `success`
- `empty`
- `recoverable-error`
- `forbidden`

预期每个状态都有明确反馈，错误状态提供重试，无权限状态提供返回入口。

## Scenario 4: Visual and Privacy Review

1. 在至少一个 iOS 和一个 Android 模拟器中检查安全区。
2. 检查系统字体放大后是否出现遮挡或横向溢出。
3. 检查所有主要触控区域不小于 44 点。
4. 检查页面未使用完整设计截图作为背景。
5. 搜索模拟数据和日志，确认不存在真实个人信息。

## Scenario 5: Performance

1. 在微信开发者工具中启用性能面板，使用本地模拟数据首次打开四个一级页面。
2. 记录各页面首次可交互时间。
3. 预期每个页面均不超过 2 秒；若超出，记录阻塞原因后再进入下一阶段。

## Expected Result

四个一级页面、各账户与资质入口状态、五种公共页面状态及性能验收均可演示，且不依赖后端接口。
